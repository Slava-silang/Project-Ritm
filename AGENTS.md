# Работа над «Ритмом»

## Начало и продолжение работы

1. Прочитай `docs/STATUS.md` и текущую задачу в `docs/TASKS.md`.
2. Сверь статус с текущей веткой, изменёнными файлами и результатами проверок. После обрыва сначала выясни, какие операции действительно завершились.
3. Перед изменением поведения прочитай соответствующий раздел `docs/SPEC.md`. Это источник согласованных требований; README содержит исходную идею.
4. Перед созданием модулей прочитай `docs/ARCHITECTURE.md`; перед настройкой окружения, запуском или упаковкой — `docs/DEVELOPMENT.md`; перед проверкой — `docs/TESTING.md`.

## Выполнение задачи

- Реализуй одну ограниченную задачу с её критериями готовности. Детализируй ближайшую работу, сохраняя общий порядок зависимостей.
- Согласованный стек: Python, PySide6, QML/Qt Quick, SQLite. Первая проверяемая платформа — Linux; Windows проверяется отдельно.
- Выполняй длительные операции вне потока интерфейса. Расчёты прогресса и правила задач держи в проверяемой Python-логике.
- Используй окружение проекта и зафиксированные зависимости. Команды из документации, помеченные как планируемые, сначала реализуй, затем проверь.
- Пользователь разрешил редактирование проекта, установку проектных зависимостей, проверки и локальные коммиты. Системные изменения выполняй в пределах фактических разрешений среды.
- Согласуй изменение пользовательского поведения, сокращение учебного выпуска, удаление пользовательских данных, публикацию и платные API-запросы. Для сетевых проверок ИИ по умолчанию используй подменный адаптер.
- Секреты и личные данные исключай из коммитов, журналов и тестовых артефактов. Тесты работают с временным профилем.
- Выбирай навыки под текущую задачу. Параллельную работу используй для независимых задач с определёнными границами файлов; количество агентов и расход согласуй перед запуском.

## Завершение шага и передача работы

1. Выполни проверки, соответствующие изменению, по `docs/TESTING.md`.
2. В `docs/TASKS.md` обнови статус и доказательства готовности задачи.
3. В `docs/STATUS.md` запиши текущую задачу, готовую часть, изменённые файлы, результаты проверок, ограничения и точное следующее действие.
4. Сохрани законченный шаг локальным коммитом, если это возможно и не включает чужие незавершённые изменения. Укажи коммит в статусе либо явно отметь, что изменения ещё не закоммичены.
5. Обновляй состояние после небольших законченных шагов: уведомление о лимите может не оставить времени на отдельную передачу.

Готовность означает выполнение критериев задачи и указание фактически пройденных проверок. Отделяй автоматические проверки, ручную проверку интерфейса и непроверенные платформы.
