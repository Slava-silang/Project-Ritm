# Графический слой сада — T39d1

Подготовлены геометрия декора, runtime-каталог PNG и данные сцены для будущего QML-поля. T39d2 подключает эти данные к странице поля/магазина/инвентаря (GARDEN_EDITOR.md). Исходная графика не менялась. Награды/оплата времени/цены/дозы/продажа неизменны; схемы основной БД v13 и сада v6 сохраняются.

## Декор в модели

Product.cell_offsets задаёт занятые клетки относительно x/y; для растений 1×1 и деревьев 2×2 прежние правила. Камень, фонарь, забор — ((0,0),), скамейка — ((0,0),(0,1)). Обозначение «2×1» в графике локальное, не горизонтальная пара глобальных x. Все украшения разрешены на grass/tilled_soil; каждая клетка скамейки может иметь любой из этих двух грунтов. Вода запрещена, границы/пересечения проверяются по всему основанию. Изменить грунт занятой клетки нельзя. Перемещение и возврат в инвентарь сохраняют ID/стадию 0. Декор не растёт и не продаётся, не входит в 80 клеток растений и не увеличивает прогресс сада.

Новых полей JSON нет: прежний инвентарь читается как раньше; размещение теперь разрешено по принятому контракту. Execute сохраняет обычные revision/UUID операции/идемпотентность и откат. Проверено повторное открытие и восстановление парной копии с размещённой скамейкой. Это расширение правил текущего читателя; поддержка чтения новых размещённых украшений прежними бинарными версиями не заявляется.

## Ресурсы

platform/garden_assets.py возвращает неизменяемый каталог GardenSprite (ID, роль, Path, canvas, anchor). Чтение/проверка выполняются в вызывающем worker до передачи данных QML, без файловых операций в функции проекции. Сначала используется ritm/assets/garden установленного пакета, в исходниках — assets/garden репозитория. Неполный установленный набор не подменяется файлами исходников.

Используются 98 PNG: 32 стадии растений/деревьев, 3 грунта, 57 переходов/углов, 4 украшения, 2 размера иконки удобрения. Ключ stone соответствует исходному decor/rock.png через catalog_kind; нового товара rock нет. Проверяются геометрия базиса 64×32/(32,16)/(-32,16), уникальность/полнота ID, размеры PNG, SHA-256 и допустимые привязки. Ошибка/отсутствие файла останавливают загрузку, без замены другим рисунком или изменения сада.

Wheel содержит два манифеста и 99 PNG: кроме 98 используемых есть прежняя вспомогательная трава plants-v1, совпадающая с environment-v1. В каталог она второй раз не попадает. Исходники генерации, references/review, макеты design-v1 и probe-v1 не включаются. Копирования/изменения игровых файлов в репозитории нет: используется force-include нужных папок при сборке. Зависимости и uv.lock не менялись.

## Проекция

ui/garden_scene.py не зависит от Qt/часов/хранилища. garden_scene(Garden, sprites) возвращает width/height, originX/Y, layers и 100 cells. Координаты — пиксели исходного рисунка, без масштаба текста приложения. Каждый слой содержит sprite/source (file URI), x/y/width/height, role и itemId (пустой у грунта/переходов). Для клетки передаются x/y, centerX/Y, terrain и itemId всего занимающего её предмета.

Центр клетки: ((x−y)×32,(x+y)×16). Привязка дерева находится в среднем центре четырёх клеток (смещение (0,16) от клетки x/y); скамейки — в среднем двух (−16,8). Сначала базовые тайлы от дальних к ближним, затем накладки, затем объекты по глубине ближайшей клетки/экранной оси/UUID. Порядок не зависит от порядка предметов в сохранённом JSON. Границы вычисляются по всем холстам, поэтому высокие деревья не обрезаются; origin смещает их и клетки в неотрицательную сцену. Пустой участок — 640×328 с боковинами.

Биты переходов: 1=(-1,0), 2=(0,-1), 4=(1,0), 8=(0,1); семейства/углы берутся по принятому контракту. На воде water_soil рисуется перед water_grass. Внутренний угол появляется только при двух боковых соседях базового грунта и диагональном соседе другого грунта. Внешняя граница поля не считается соседней поверхностью.

cell_at(scene, px, py) выполняет обратную проекцию по ромбам поверхности, не прямоугольникам PNG/боковинам; возвращает (x,y) либо None. Точные общие границы имеют детерминированное полуоткрытое правило округления, без двойного выбора. Будущий QML должен сначала убрать смещение/масштаб области просмотра. Просмотр 1×/2× и smooth=false относятся к T39d2, а не к повторному изменению исходных PNG.

В иллюстративном environment-v1/review/scene-layout.json map хранится как map[x][y], а в модели terrain[y*10+x]. Тест переводит этот формат явно; не переносить демонстрационную карту как плоские строки без транспонирования. Синтетическая сцена проходит правила модели: 21 клетка растений, 16 взрослых, два дерева, вся графика/грунты/декор. Экранные x/y/показатели макета не являются пользовательскими данными.

## Проверка поставки

scripts/check_garden_wheel.py проверяет состав wheel, устанавливает его без зависимостей/сети в временную папку и запускает отдельный Python из каталога с кириллицей вне репозитория. Проверяется фактический __file__ установленного пакета, ресурсный путь, декодирование 98 PNG через Qt, геометрия сцены и выбор всех 100 клеток. Это проверка Python-пакета с текущей средой зависимостей; не standalone-релиз без Python и не поддержка Windows. Nuitka/T30–T32 остаются отложенными.
