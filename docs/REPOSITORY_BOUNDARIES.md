# Границы репозитория и первичная проверка R01

Проверено 25 ноября 2026, исходная точка ece8ba9. Это инвентаризация и
проверка известных шаблонов секретов, не заключение о полной безопасности.

## Разделение

- Текущий репозиторий — desktop: src/ritm, тесты, документация и материалы
  разработки. integrations и локальные OAuth callback входят в клиент;
  их нельзя исключать как будущий облачный сервер.
- Сервер синхронизации/Telegram T41–T42 пока не реализован. Он размещается
  в отдельном закрытом Git-репозитории; секреты и рабочие данные остаются
  вне Git даже там. Новый репозиторий в этом шаге не создавался, код не
  переносился, публикация/настройка GitHub не выполнялись.
- В desktop допустимы клиентский протокол и обезличенные контрактные тесты.
  Рабочие серверные конфигурации, БД, ключи и копии профилей сюда не входят.
- .gitignore дополнен корневыми server/backend/profiles/logs/attachments,
  именами файлов настроек/авторизации профиля и PKCS12/PFX. Это защита от
  случайного добавления: она не удаляет ранее отслеживаемые файлы из истории
  и не заменяет контроль содержимого перед коммитом.
- Для экспериментов использовать временный профиль вне checkout. Файлы
  профиля не должны становиться ресурсами приложения.

## Что фактически проверено

1. Через git rev-list --objects --all и git cat-file --batch прочитаны
   1292 уникальных blob из 89 локальных коммитов: 1097 текстовых и 195
   бинарных объектов. Проверены высокоспецифичные шаблоны приватных ключей,
   OpenAI/Anthropic-подобных ключей, GitHub-токенов, AWS AKIA, Google API/
   client secret, Telegram bot token, JWT и HTTP URL с учётными данными.
   Во втором проходе шаблоны искались также в байтах бинарных объектов.
   Совпадений не выявлено; значения из содержимого не выводились в отчёт.
2. Через git log --all --name-only проверены 493 исторических пути.
   Имен .env, auth/credentials/token JSON, SQLite/DB, PEM/KEY/P12/PFX
   не обнаружено. HTTP remote URL дополнительно проверены на userinfo и
   типовые секретные параметры без вывода самих URL: кандидатов нет.
3. Бинарные объекты — 192 PNG и 3 JPG, в assets/garden, assets/pets и
   docs/design/dark. Бинарных БД/архивов среди этой группы не обнаружено.
4. git check-ignore --no-index: 10 запрещённых примеров игнорируются,
   5 нужных примеров (включая .env.example, тест, клиентский OAuth и
   манифест графики) остаются разрешёнными. Всего 15 проверок passed.
5. Свежий offline Python-wheel: 212 записей. Проверены отсутствие tests,
   server/backend, sources/references/review, probe/samples/design, .git,
   баз и ключей; запрещённых записей нет. Main.qml совпадает с рабочим
   файлом. Артефакт /tmp/ritm-r01-wheel, конфигурация pyproject.toml прежняя.

## Границы результата и следующие проверки

Проверены только локально доступные Git refs; GitHub/forks/удалённые кеши не
запрашивались. Шаблоны не доказывают отсутствие произвольных паролей,
неизвестных форматов токенов, персональных данных или секретов на картинке.
Визуальное содержимое всех 195 исторических изображений не проверялось.
Перед публичной отправкой/выпуском требуется ручная проверка публикуемых
изображений, логов и артефактов — критерий T31/RELEASE_CHECKS.md.

Пользовательские неотслеживаемые assets/theme_* не редактировались и не входят
в проверенную Git-историю; их содержимое проверяется при будущем включении
в репозиторий/поставку. Личный профиль/ключи ОС не открывались. Эти проверки
не заменяют R02: аудит входа, хранения токенов и состава сетевых запросов.

Python-wheel не является самостоятельной поставкой. Устаревшая конфигурация
pyside6-deploy/Nuitka должна быть обновлена и проверена в T30; отсутствие
лишних файлов в wheel не доказывает состав будущего установщика.
