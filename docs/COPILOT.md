# Подключение Copilot — T40b

## Готовая часть T40b1

`integrations/copilot.py` реализует текстовый Adapter для официального
`github-copilot-sdk==0.1.32`. Зависимость необязательная, закреплена в uv.lock;
обычный запуск ChatGPT/демо не импортирует SDK. Это ещё не доступное из
интерфейса подключение: вход, проверка аккаунта/списка моделей и выбор
Copilot остаются T40b2. Реальные аккаунты и запросы не проверены.

Адаптер предназначен для существующего worker AssistantController, не для
вызова из потока QML. Получает явно выбранную модель, общий prepare_text,
новый SDK-клиент/сессию на запрос и возвращает текст предложения. Последующий
разбор, редактирование и подтверждение остаются в приложении; запись задач
из SDK не выполняется. Пять операций: create/split/schedule/update/mail.
Capabilities — только text: выбранные текстовые материалы читаются обычным
prepare_sources, бинарные изображения/документы отклоняются до запуска SDK.

Клиент работает через stdio с bundled CLI закреплённого platform-wheel.
Рабочая папка и config_dir сессии временные; рабочий каталог проекта не
передаётся. available_tools пустой, permission и pre-tool hook запрещают
вызовы инструментов. system_message replace содержит правила «Ритма»;
встроенные guardrails SDK в этом режиме заменяются этими правилами, поэтому
запрет инструментов задаётся отдельно. Infinite sessions выключены.
Пустые mcp_servers/skill_directories в SDK не гарантируют отключения всех
пользовательских настроек CLI; полная изоляция CLI-конфигурации и входа
проверяется в T40b2 до подключения к UI.

Логи CLI выключены. Из окружения процесса исключаются COPILOT_/GITHUB_/GH_/
OPENAI_/ANTHROPIC_/AZURE_OPENAI_ переменные, чтобы не подставить сторонний
токен/адрес API вместо выбранного аккаунта. Вход пока читается только самим
SDK при явном вызове адаптера, с use_logged_in_user=True; «Ритм» не извлекает
и не сохраняет токен. Ошибки SDK наружу заменяются сообщениями без исходного
текста исключения. Это часть контракта реализации, не проведённый аудит.

Отмена проверяется во время запуска, проверки входа, создания сессии и
ответа; общий timeout по умолчанию 120 секунд. Cleanup пытается abort,
delete_session и stop, при ошибке/таймауте stop — force_stop. Каждый шаг
cleanup ограничен 3 секундами ожидания; SDK содержит собственные синхронные
операции остановки процесса, поэтому это не жёсткая гарантия времени
завершения системного процесса. Ошибка удаления сессии не мешает остановке,
но отсутствие остаточных файлов настоящего CLI ещё не подтверждено.
Временная папка удаляется средствами Python.

## Проверенное окружение

```bash
uv sync --locked --extra copilot --offline
uv run --locked --no-sync pytest -q tests/test_copilot.py tests/test_copilot_sdk.py tests/test_assistant_prompt.py tests/test_file_context.py tests/test_task_updates.py
```

Первая команда проверена после загрузки пакетов; для сохранения средств
упаковки в том же окружении добавить `--group packaging` (потребуется сеть,
если их архивов нет в кеше). SDK-контракт проверяется без запуска CLI через
подменный JSON-RPC; при отсутствии optional SDK соответствующий тест skip.
Функциональные fake-тесты не требуют SDK. Windows/реальный вход/квоты и
обработка ошибок подписки остаются непроверенными. Нет автоматического
перехода на API-ключ, BYOK или другую модель.
