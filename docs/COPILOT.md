# GitHub Copilot — T40b

## Запуск и использование

Подключение необязательное. Для запуска из исходников с Copilot:

```bash
uv run --locked --extra copilot ritm
```

Чтобы сохранить установленные средства сборки в этом же окружении, добавить
`--group packaging`. Без extra приложение работает как прежде, а панель
Copilot сообщает об отсутствии компонента. SDK закреплён в uv.lock:
`github-copilot-sdk==0.1.32`, platform-wheel содержит bundled CLI 1.0.2.
Загрузка пакета не означает входа в аккаунт.

«Помощник» → «Подключения ИИ» → «GitHub Copilot» → «Войти через GitHub».
Официальный CLI открывает браузер; при необходимости в панели показывается
одноразовый код и кнопка фиксированной страницы github.com/login/device.
После входа загружается список доступных моделей (без запроса модели).
Затем выбрать модель и нажать «Использовать Copilot» — вход сам не меняет
активное подключение. «Проверить сохранённый вход» повторяет проверку
аккаунта/списка моделей после перезапуска, только по действию пользователя.

«Отключить в Ритме» сбрасывает подключение в приложении, при активном
Copilot включает локальный режим. Это не глобальный logout CLI: его запись
в системном хранилище может использоваться другими программами. Сохранённый
вход остаётся, разрешение отзывается в настройках GitHub. Нет автоматического
выхода из других клиентов пользователя. Если защищённое хранилище недоступно,
CLI отказывает в сохранении: stdin закрыт, согласие на plaintext не передаётся.

При переключении подключения/активной модели прежний черновик и отправляемый
контекст очищаются, начинается новый диалог. История сохраняет отдельные
scope/provider/model, метка Copilot отлична от ChatGPT; чужой scope нельзя
продолжить. Изменение модели/выход неактивного ChatGPT не сбрасывают Copilot.

## Реализация и данные

`integrations/copilot_account.py` — официальный login subprocess и SDK
start/auth.getStatus/models.list. `ui/connection.py` управляет ими в одном
worker вместе с ChatGPT; QML получает состояние/имя/модели/одноразовый код,
не исходный вывод CLI и не токен. `CopilotPane.qml` — отдельная панель.

Конфигурация/распакованный CLI находятся в `<профиль>/copilot-cli/`.
Родитель создаётся с mode 0700 на POSIX, GH_CONFIG_DIR указывает на собственный
пустой каталог. COPILOT_HOME и --config-dir заданы явно. Обычные ~/.copilot и
конфигурация gh не используются. Папка игнорируется Git; backup включает
только разрешённые задачи/вложения/сад, не Copilot. Кеш CLI может занимать
существенное место; не переносить его вместе с учебными материалами.

При login запускается bundled CLI без shell с --no-auto-update, stdin
DEVNULL, ограниченным чтением вывода. Передаются только коды из ожидаемой
строки с фиксированным GitHub URL. Ожидание — 300 секунд, отмена останавливает
дочерний процесс (terminate, при необходимости kill). Официальный login CLI
может вести собственный журнал в своей папке; он не выводится в интерфейс,
не попадает в backup/Git. Подробный аудит содержимого/хранения остаётся R02.

`integrations/copilot.py` выполняет текстовые create/split/schedule/update/mail
в worker AssistantController, с общим prepare_text и прежними парсерами/
подтверждением. Новый клиент/сессия на запрос, cwd/config_dir сессии временные.
available_tools пустой, permission/pre-tool запрещают инструменты; CLI
получает --disable-builtin-mcps/--no-custom-instructions, изолированный home.
Infinite sessions выключены. system_message replace заменяет встроенные
правила SDK правилами «Ритма», поэтому запрет инструментов задан отдельно.

Capabilities только text: текстовые материалы обрабатывает prepare_sources,
бинарные картинки/документы не отправляются этим подключением. Модель задаётся
явно из списка; ambient API-переменные исключены, BYOK/fallback отсутствуют.
Timeout запроса 120 секунд, проверки аккаунта/моделей — 60. Cleanup пытается
abort/delete_session/stop, затем force_stop при неудаче stop. SDK содержит
синхронные операции завершения: время закрытия ОС не гарантируется жёстко
только asyncio-таймаутом. Внешние ошибки заменяются фиксированными сообщениями.

## Проверки и ограничения

140 сценариев passed (39,11 с): fake lifecycle/вход/UI/переключение, настоящий
SDK через stub JSON-RPC, прежний ChatGPT на локальном сервере. Дополнительно
native Linux GUI на подменах passed; результаты/последующие уточнения TESTING.
Настоящий CLI в отдельном временном профиле с use_logged_in_user=False:
start → auth status (false) → force_stop → выход из loop прошли, без входа
или запроса к модели. Справка CLI подтвердила поддерживаемые флаги/login.

В ограниченной среде этот probe зависал на завершении asyncio executor;
минимальный asyncio.to_thread без SDK воспроизвёл то же (timeout 4 с).
Оба примера прошли в обычной среде; приложение ради ограничения тестовой
среды не обходилось. Первая регрессия 137 passed/2 failed обнаружила null
bindings новой панели при отсутствии connection; исправлены, финальные 140
выше. Временная диагностика не внесена в код приложения.

Реальный OAuth-вход/подписка/квоты, настоящий запрос, Windows и standalone
пока не проверены. Нужен доступный план/политика организации; запросы расходуют
его лимиты. Это не гарантия бесплатности/неограниченности и не аудит R02.
