# Окружение, запуск и выпуск

На 13 ноября 2026 года T01–T22, T12a и T17a завершены: из исходников доступны задачи, фильтры, корзина и календарь недели/месяца с созданием, переносом и изменением блоков и самостоятельных событий. Самостоятельная Linux-поставка пока остаётся на T02 со стартовым окном; она не содержит текущих функций.

## Уже установлено на текущем компьютере

Проверено из текущей сессии: Linux Mint 22.3, x86_64, Cinnamon/X11; Python 3.12.3; Git; uv; GCC/G++; make. Стандартный модуль `sqlite3` доступен (SQLite 3.45.1).

В `.venv` установлены PySide6 6.12.0, pytest 9.2.0 и Ruff 0.17.4; группа упаковки добавляет Nuitka 4.2.2, ordered-set 4.1.0, zstandard 0.25.0 и Linux patchelf 0.19.3.0. Версии фиксируются в `uv.lock`. Системный Python не изменён. Для компиляции используются имеющиеся GCC 13, readelf и заголовки Python 3.12.

## Воспроизведение окружения

Из каталога репозитория выполнить `uv sync --locked`. Требуется Python 3.12; `.python-version` задаёт эту ветку. PySide6 — зависимость приложения, pytest и Ruff — группа разработки, устанавливаемая по умолчанию. `.venv` создаётся локально и исключена из Git.

При появлении моделей настроить проверку аннотаций типов с учётом Qt-привязок. Инструменты упаковки устанавливать при T02 отдельно от обычных runtime-зависимостей и фиксировать рабочую конфигурацию.

Системный Python не заменять. Отдельная установка полного Qt SDK обычно не требуется: PySide6 wheels включают библиотеки Qt. SQLite — встроенная локальная библиотека; сервер базы данных устанавливать не нужно. Qt Creator или редактор с поддержкой QML необязателен для командного запуска.

Источник: [Qt for Python: Getting Started](https://doc.qt.io/qtforpython-6/gettingstarted.html).

## Запуск при разработке

Проверенные команды:

```sh
uv sync --locked
uv run ritm
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run pyside6-qmllint src/ritm/qml/Main.qml src/ritm/qml/CalendarPane.qml src/ritm/qml/DayTimeline.qml src/ritm/qml/StatisticsPane.qml src/ritm/qml/Appearance.qml src/ritm/qml/AssistantDialog.qml src/ritm/qml/ConnectionPane.qml
```

Диагностика: `uv run ritm --smoke-test` открывает и закрывает окно автоматически; `uv run ritm --version` выводит версию. Альтернативный запуск: `uv run python -m ritm`.

Из другого каталога: `uv run --project /полный/путь/к/Project-Ritm --locked ritm`. В T01 реальная команда проверена из `/tmp`; оба entrypoint дополнительно проверены тестами из папки с пробелом и кириллицей.

В среде без экрана автотесты используют Qt offscreen и временные XDG-каталоги. Реальный рабочий стол проверять отдельно. Если ограниченная среда агента не даёт доступа к X11, это не означает отсутствия библиотек: проверить реальный запуск в разрешённой пользовательской сессии.

Обычный цикл: изменить Python/QML → выполнить подходящие проверки → запустить интерфейс → сохранить результат. Релизная компиляция при каждом изменении не требуется.

QML загружается относительно пакета, а не текущего каталога. С T08 обычный запуск пишет в Qt AppDataLocation: на проверенном Linux это `~/.local/share/ProjectRitm/Ritm/tasks.sqlite3`. Исходники и папка поставки данных не содержат.

Отдельный набор для разработки/ручной проверки:

```sh
uv run --locked ritm --profile /tmp/ritm-demo-profile
```

Указанная папка создаётся при первом запуске, следующие запуски с тем же --profile открывают тот же набор. Без --profile обычный запуск использует личный профиль; --smoke-test использует автоматически очищаемую временную папку. Автотесты всегда задают временные папки. Крестик скрывает окно в доступный трей, сохраняя фокусировку. «Приложение» → «Выйти из приложения» или меню трея предлагают завершить активную сессию и выйти. Без трея крестик выполняет выход с тем же подтверждением. Ctrl+C и SIGTERM завершают процесс, а восстановление открытой сессии доступно при следующем запуске.

В интерфейсе: «+ Задача» → название, описание, необязательные сложность/минуты/дедлайн → «Сохранить». Пункты добавляются в карточке, переименовываются через «⋯»; веса меняются кнопкой «Веса». Срок вводится как ДД.ММ.ГГГГ ЧЧ:ММ в местном времени. Пустое поле означает отсутствие срока. Отмена формы не сохраняет.

С T09 поиск проверяет название, описание и шаги; фильтры «Активные», «Выполненные», «Все задачи» сочетаются с категорией. Категорию можно выбрать или ввести новую в форме задачи. Просроченные выделены текстом и цветом; группы обновляются автоматически без уведомлений.

«Удалить» в карточке и «×» у обоих уровней открывают подтверждение переноса в корзину. Через «Корзина» → «Восстановить» можно вернуть удалённое и после перезапуска. Если родитель тоже удалён, сначала восстановите его. Если состав/веса задачи менялись, возвращаемый шаг получает новую автоматическую долю; остальные изменения сохраняются. Для окончательной очистки отметьте записи в корзине, нажмите «Удалить выбранное» и подтвердите. Если отдельно удалённые пункты относятся к выбранной задаче, отметьте их тоже.

На узком окне карточка занимает основную область; «К списку» возвращает поиск, фильтры и корзину. При открытии существующего профиля v1–v9 новая версия переводит схему в v10 одной транзакцией: сохраняет задачи/корзину, добавляет недостающие таблицы календаря и поддержку событий без задачи, сохраняя существующие блоки. Метаданные остаются в tasks.sqlite3. Копии файлов создаются в подпапке attachments при добавлении вложений. Старую версию программы с профилем v10 не использовать; текущую разработку запускать заново через uv.

Проверка полного QML-сценария (программные клики Qt, временная база и новый процесс):

```sh
uv run --locked pytest tests/test_task_ui.py -q
RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_task_ui.py::test_qml_task_scenario_and_restart -q
```

Первая команда использует offscreen; вторая требует настоящую X11-сессию. Кадры остаются в pytest-временной папке; осмотренные изображения T08 скопированы в игнорируемую `artifacts/t08/`.

T09, включая удаление и новый процесс восстановления:

```sh
uv run --locked pytest tests/test_task_navigation.py -q
RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_task_navigation.py::test_navigation_qml_scenario_and_trash_restart -q
```

Сценарии используют Qt Quick software renderer; на X11 это настоящий backend xcb. Тест ожидает ответ оконного менеджера при изменении размера. Осмотренные кадры T09 — в игнорируемой `artifacts/t09/`.

`uv build --wheel` проверен: `dist/project_ritm-0.1.0-py3-none-any.whl` содержит Main.qml. Это Python-пакет, не самостоятельная программа для компьютера без Python.

Источник: [uv: Working on projects](https://docs.astral.sh/uv/guides/projects/).

## Самостоятельная Linux-сборка

Используются `pyside6-deploy`, Nuitka и явный режим standalone. Зависимости упаковки устанавливаются отдельно:

```sh
uv sync --locked --group packaging
uv run --locked --group packaging python scripts/build_linux.py
```

Команда работает из любого текущего каталога при указании полного пути к скрипту и проекта через `uv --project`. Она создаёт рабочую копию `pysidedeploy.spec` в `build/`, поэтому автоматически найденные абсолютные пути не загрязняют отслеживаемую конфигурацию. Установкой пакетов управляет uv; deploy запускается с `--no-install`.

Результат: папка с исполняемым файлом, Python runtime, Qt-библиотеками/плагинами, QML, изображениями и прочими зависимостями. На другом компьютере распространяется вся папка, а не один исполняемый файл из неё. Отдельный установленный Python пользователю не нужен, но остаются требования к ОС, архитектуре и системным библиотекам.

Nuitka компилирует Python-код, сохраняя зависимость от среды выполнения Python/libpython. Это не превращает всё приложение в программу без Python runtime.

Точка входа упаковки — `src/main.py`, вызывающая тот же `ritm.app:main`. QML включается в `ritm/qml`, относительно пути скомпилированного модуля. Версия хранится в `ritm.__version__`; Hatchling получает метаданные из этого же источника. Исполняемая программа не зависит от наличия метаданных установленного Python-пакета.

После успешной сборки:

- `dist/ritm-linux-x86_64/ritm.bin` — исполняемый файл;
- `dist/ritm-linux-x86_64/` — вся поставляемая папка;
- `dist/ritm-0.1.0-linux-x86_64.tar.gz` — архив этой папки;
- одноимённый `.tar.gz.sha256` — контрольная сумма;
- `build/compilation-report.xml` — локальный отчёт Nuitka.

Версия и архитектура в именах архива определяются скриптом. Папки build/dist/src/deployment исключены из Git. Скрипт проверяет запуск до замены предыдущего результата; окончательную переносимость дополнительно проверяет отдельная команда ниже.

Запуск пользователем из папки программы:

```sh
./ritm.bin
```

Папка передаётся целиком. Python, uv, Qt SDK и Docker конечному пользователю не нужны. Остаются системные графические библиотеки и совместимая Linux-система; Windows требует своей сборки.

### Проверка переноса и чистого окружения

```sh
uv run --locked --group packaging python scripts/check_linux_build.py --relocation-only
uv run --locked --group packaging python scripts/check_linux_build.py --build-image
```

Первая команда проверяет настоящую копию программы в папке с кириллицей и пробелом, версию и загрузку QML. Вторая дополнительно создаёт тестовый Ubuntu 24.04-образ и запускает бинарный файл без установленного Python, исходников и сети, от непривилегированного пользователя с read-only поставкой. Docker используется только для разработческой проверки. С `--directory` можно проверить папку, извлечённую из архива.

Системные библиотеки тестового стенда перечислены в `packaging/linux/Dockerfile.smoke`, включая выявленную зависимость QtNetwork от `libgssapi-krb5-2`. Этот контейнер проверяет offscreen-запуск. Настоящий X11/Wayland проверяется отдельно; наличие Qt-плагина не доказывает поддержку всего рабочего окружения.

### Особенности среды сборки

Nuitka 4.1.1 воспроизводимо завершала бинарный файл с SIGABRT при кириллице в пути до входа в приложение. Проверка переноса добавлена до изменения инструмента; используется ветка Nuitka 4.2 с зафиксированной версией в lock-файле.

На 4.2.2 проверка прошла, включая реальный X11 после распаковки в кириллическую папку и отдельный контейнер без Python. Архив текущей сборки — 93 383 160 байт (около 89 МиБ), распакованная папка — около 288 МиБ. Размер и контрольная сумма меняются при пересборке; актуальный SHA256 записывается рядом с архивом. Эти результаты не подтверждают запуск на всех Linux-дистрибутивах.

В ограниченной среде агента служебный `ldd` вызывал 32-битный загрузчик, заблокированный с SIGSYS. Такая сборка останавливается и повторяется с разрешённым доступом к средствам сборки; система и код Nuitka вручную не изменяются. При обычном локальном запуске из пользовательского терминала эта особенность ограниченной среды не применяется.

Предупреждения deploy об отсутствии необязательного `.pyproject`, повторном включении Main.qml и неиспользуемой Linux-иконке в standalone-режиме сами по себе не означают успешную или неудачную сборку: результат проверяется реальным запуском. `uv build` создаёт Python-дистрибутив и не заменяет standalone.

В Linux для упаковки могут потребоваться readelf, patchelf, заголовки Python и компилятор. Часть устанавливается инструментами в окружение; необходимость системных пакетов проверять по фактической диагностике. При Windows-сборке проверить поддерживаемый компилятор и средства анализа DLL. Вручную заранее устанавливать полный набор SDK на Linux не требуется.

Источники: [pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html), [Nuitka: User Manual](https://nuitka.net/user-documentation/user-manual.html).

## Форматы выпуска

Текущий артефакт — standalone-папка Linux в архиве. Позднее можно выбрать удобную оболочку: например, AppImage для Linux и установщик/portable-папку для Windows. Выбор формата сам по себе не является доказательством переносимости.

Сборки готовить отдельно в соответствующей ОС и для целевой архитектуры: Linux-артефакт не заменяет Windows-артефакт. Сначала проверить минимальную упаковку, потом полный состав. Зависимости Linux могут требовать сборки на достаточно старой поддерживаемой базе; обещание «на любом Linux» не давать.

## Проверка релиза

- Запустить в чистом поддерживаемом окружении без средств разработки и исходников.
- Проверить ресурсы, Qt-плагины и запись данных в пользовательский профиль.
- Пройти сценарии TESTING, включая вложения и восстановление копии.
- Зафиксировать точную ОС/архитектуру, формат, версию, ограничения и контрольную сумму артефакта.
- Перед публичным распространением выбрать лицензию проекта и проверить требования реально используемых зависимостей. Публикация согласуется отдельно.

API-ключ поставляется самим пользователем в настройках. Без ключа локальные задачи, календарь, таймер и обычные реакции компаньона работают.

## Проверка данных календаря T10

```sh
uv run --locked pytest tests/test_calendar_blocks.py -q
```

WorkBlock и CalendarService доступны как Python-модель/сценарии; с T11 календарь и создание блоков доступны через окно. Тесты используют только временные базы, отдельный процесс и системные правила часовых поясов (zoneinfo). Созданные блоки хранятся в общей SQLite, а не в отдельном файле. Перед самостоятельным выпуском приложение потребуется пересобрать; текущий архив остаётся на T02.

## Календарь T11

Откройте вкладку «Календарь». По умолчанию показана неделя; кнопки «Месяц», стрелки и «Сегодня» меняют период. Нажатие числа выбирает день, его события перечислены под сеткой. «+ Блок» открывает форму задачи/начала/окончания; кнопка в карточке заранее выбирает её задачу. Для интервала через полночь укажите следующую дату окончания. Пересечения и превышение срока сохраняются с предупреждением; отмена не записывает данные. Событие открывает соответствующую карточку задачи.

```sh
uv run --locked pytest tests/test_calendar_ui.py -q
RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_calendar_ui.py::test_calendar_qml_and_restart -q
```

Сценарии создают временные профили и проверяют новый процесс приложения. Осмотренные кадры — artifacts/t11/. На T11 мышиный перенос и изменение длительности ещё относятся к T12. Схема остаётся v3, новые внешние файлы не добавляются.

`uv build --wheel --offline` проверен: Main.qml, CalendarPane.qml и Python-модули присутствуют. Извлечённый пакет успешно запущен из другой рабочей папки с имеющимся окружением Qt. Это не standalone; текущий самостоятельный архив всё ещё T02. Конфигурация pyside6-deploy перечисляет оба QML-файла для будущей пересборки.

## Перенос и растягивание T12

Ручка ↔ на карточке блока переносит его на другой день. Ниже сетки расположена шкала выбранного дня: перетащите тело блока вверх/вниз, а нижний край — для изменения длительности (шаг 15 минут). У ночного блока используйте день начала для сдвига на шкале и день окончания для растягивания. Кнопка ⋯ открывает точную форму. Escape отменяет жест; ошибка возвращает прежнее положение. При конфликте с изменением в другом окне обновите календарь и повторите.

```sh
uv run --locked pytest tests/test_calendar_drag.py -q
RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_calendar_drag.py::test_pointer_gui_changes_and_failure_rollback -q
```

Проверены три QML через qmllint и включение в wheel; извлечённый пакет запускается из другой папки. Кадры native-проверки — artifacts/t12/. Полная самостоятельная сборка не обновлялась: запускайте текущую версию через `uv run ritm`.

## Самостоятельные события T12a

В календаре нажмите «+ В расписание», выберите «Событие», введите название и начало/окончание. Создание работает и без задач. Клик по фиолетовому событию открывает редактирование; ручка ↔ и дневная шкала работают как для блоков задач. Событие не входит в плановое время задачи. Все записи находятся в прежнем tasks.sqlite3, дополнительных файлов данных нет.

Проверка: `uv run --locked pytest tests/test_calendar_events.py`. Для реального X11-сценария добавьте `RITM_UI_PLATFORM=xcb`. Проверки создают временные профили; осмотренные кадры — artifacts/t12a/.

## Фокус-сессии T13

Из карточки задачи нажмите «Начать фокус». Пустое поле запускает секундомер, целое положительное число минут задаёт план. Пауза и завершение доступны также из календаря. После завершения открывайте «История фокуса» в карточке. После сна компьютера или блокировки Cinnamon сессию нужно продолжить вручную. При закрытии окна с текущей сессией выберите «Остаться» или «Завершить и выйти».

Проверка с временными профилями: `uv run --locked pytest tests/test_focus.py`. Для сценария в реальном X11 добавьте `RITM_UI_PLATFORM=xcb`.

В «Истории фокуса» кнопка «+ Запись вручную» добавляет прошедший интервал, а «Исправить» меняет его длительность в формате ЧЧ:ММ:СС. При восстановлении можно ввести окончание или подтвердить последнюю сохранённую отметку.

## Статистика T16

Откройте вкладку «Статистика» и выберите неделю стрелками. Кнопка «Эта неделя» возвращает текущий период. Шкала прогресса использует задачи с дедлайнами этой недели, а счётчик завершений использует даты завершения. Для задач, завершённых до обновления, отображается отдельный счётчик без даты. Время фокуса показано по завершённым сессиям.

Проверка с временным профилем — `uv run --locked pytest tests/test_weekly_statistics.py`.

В карточке главной задачи нажмите «Вложения», возле подзадачи или пункта — «Файлы». ## Резервные копии T19

Нажмите «Копии» → «Создать копию» для ручного архива. В «Выбрать папку» можно указать другое место. По умолчанию используется подпапка backups профиля. При первом запуске за локальный день создаётся автоматическая копия. В выбранной папке хранятся семь последних автоматических копий этого профиля.

«Восстановить…» проверяет выбранный ZIP и показывает дату. Кнопка «Заменить данные» применяет архив к текущему профилю. Для проверки восстановления используйте отдельный `--profile`. Диагностический `--smoke-test` пропускает автоматическое копирование.

Проверка — `uv run --locked pytest tests/test_backup.py`.

## Оформление T20

Нажмите «Вид», выберите условную тему и масштаб, затем «Применить». Четыре темы будут оформлены полностью после общего дизайна. Настройки сохраняются в appearance.json выбранного профиля. Клавиатурные действия перечислены в диалоге, основные — Ctrl+N, Ctrl+F и Ctrl+1…4.

Проверка — `uv run --locked pytest tests/test_appearance.py`.


## T21 — трей и автозапуск

«Приложение» открывает настройки запуска и команду выхода. Автозапуск выключен по умолчанию. Изменения применяются отдельной кнопкой; закрытие настроек без применения ничего не записывает. Можно выбрать обычный или скрытый старт. При недоступном трее скрытый старт показывает окно; исчезновение трея возвращает скрытое окно в течение секунды. В главном окне показано объяснение поведения без трея. Ctrl+C/SIGTERM сохраняют прежний путь завершения процесса и последующего восстановления открытой сессии.

Linux-адаптер создаёт только после включения пользовательский `$XDG_CONFIG_HOME/autostart/project-ritm-<хеш профиля>.desktop` (обычно `~/.config/autostart/`). Отключение удаляет этот файл; разные профили имеют разные имена. Файл содержит команду, путь профиля и режим запуска; в резервную копию данных не входит. Запись атомарная и идёт вне UI-потока. Команда использует `/usr/bin/env --`, без shell. При разработке запускается Python именно текущего окружения с `-m ritm`; в Nuitka — исполняемый файл поставки. После переноса исходников/окружения или поставки выключите и включите автозапуск заново. Файлы в системных каталогах не создаются.

`uv run --locked ritm --profile /tmp/ritm-demo-profile --start-hidden` позволяет отдельно проверить скрытый запуск. При уже открытом профиле второй процесс отказывается открывать ту же базу. Видимость и настройки будущего компаньона относятся к T28–T29. Windows-автозапуск ещё не реализован; Wayland не проверен. Выпуск T02 не пересобирался; Widgets и DBus добавлены в конфигурацию будущей сборки T30.

Проверки: `uv run --locked pytest tests/test_desktop.py -q`. Автотесты изменяют автозапуск только во временной папке. Реальная проверка X11: `QT_QPA_PLATFORM=xcb QT_QUICK_BACKEND=software uv run --locked python tests/ui_desktop_scenario.py /tmp/ritm-desktop-new-profile native` (новая папка на каждый запуск).


## T22 — проверяемые черновики помощника

Обычный запуск из исходников показывает «Помощник (тест)». Это локальный шаблон, а не подключённая модель. Запрос и выбранная задача никуда не отправляются, учётные данные не требуются. Для новой задачи введите описание, получите черновик, при необходимости нажмите «Изменить черновик», исправьте поля/подзадачи/веса и нажмите «Проверить изменения». Только «Подтвердить и сохранить» записывает задачу. Веса вводятся по порядку всех подзадач первого уровня через точку с запятой, пустое поле возвращает автоматическое распределение. Дедлайн — ДД.ММ.ГГГГ ЧЧ:ММ в местном времени.

Второй режим предлагает новые подзадачи к выбранной работе. Он сохраняет существующие пункты, их UUID, выполнение и поля главной задачи; новые ветки добавляются через обычные правила прогресса. Предпросмотр показывает итоговые веса всего первого уровня. Изменение исходной задачи после запроса требует нового черновика. Отклонённый, отменённый или запоздавший ответ ничего не записывает. Окно немодальное; его можно закрыть для отмены запроса.

SQLite v10 добавляет applied_proposals: ID черновика, хеш результата и ID задачи без текста запроса/ответа. Запись дерева и квитанции выполняется одной транзакцией. Повтор не создаёт задачу снова, включая повтор после её удаления. Квитанции входят в новые резервные копии; архивы v9 проверяются по точной старой схеме и мигрируются только во временной папке восстановления. Черновики и запросы пока только в памяти; история и полноценный чат — T24. Вход через аккаунт — T23.

Проверки T22: `uv run --locked pytest tests/test_assistant_drafts.py -q`; настоящий X11: `RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_assistant_drafts.py::test_assistant_gui_and_cancelled_late_response -q`. Тесты используют временные профили и подменные адаптеры. Самостоятельная поставка пока T02, AssistantDialog.qml добавлен в конфигурацию будущей пересборки.


## T23 — подключение по аккаунту (ожидает реальной проверки)

Добавлены зафиксированные keyring 25.7.0, PyJWT 2.15.1, cryptography 50.0.2 и их зависимости. Окружение обновлено через `uv add`; воспроизведение — `uv sync --locked`. Системный Python не изменён.

Порядок входа, отдельное согласие на тест и ограничения описаны в [CHATGPT_CONNECTION.md](CHATGPT_CONNECTION.md). На старте приложение не читает токены и не выполняет сетевые запросы. Новая панель включена в pysidedeploy.spec, но самостоятельная сборка пока T02.

Для X11: `RITM_UI_PLATFORM=xcb uv run --locked pytest tests/test_chatgpt.py::test_connection_gui_with_fake_account -q`. Системный браузер и реальные аккаунты в этих проверках не используются. В T23 финальная живая проверка ещё не выполнена.
