# Окружение, запуск и выпуск

На 8 ноября 2026 года подготовлены только документы. Ниже отделены факты проверки машины, выбранный рабочий порядок и команды, которые появятся при реализации T01–T02.

## Уже установлено на текущем компьютере

Проверено из текущей сессии: Linux Mint 22.3, x86_64, Cinnamon/X11; Python 3.12.3; Git; uv; GCC/G++; make. Стандартный модуль `sqlite3` доступен (SQLite 3.45.1).

PySide6, pytest и Nuitka в проверенном системном Python не найдены. Проектного окружения пока нет. Qt Creator и patchelf в PATH не найдены. Наличие/отсутствие проектных пакетов после установки проверять через uv, а не через системный Python.

## Что установить при T01

- Создать `pyproject.toml`, окружение `.venv` через uv и lock-файл.
- Исходный кандидат версии Python — уже имеющийся 3.12. Проверить совместимость выбранных стабильных версий PySide6 и инструментов перед фиксацией.
- Установить PySide6 как зависимость приложения, pytest и Ruff как зависимости разработки. Конкретные версии фиксируются lock-файлом при реальной установке.
- Выбрать и настроить проверку аннотаций типов при появлении моделей, учитывая качество Qt-привязок.
- Инструменты упаковки устанавливать в проектное окружение/отдельную группу; сохранить рабочие версии и конфигурацию.

Системный Python не заменять. Отдельная установка полного Qt SDK обычно не требуется: PySide6 wheels включают библиотеки Qt. SQLite — встроенная локальная библиотека; сервер базы данных устанавливать не нужно. Qt Creator или редактор с поддержкой QML необязателен для командного запуска.

Источник: [Qt for Python: Getting Started](https://doc.qt.io/qtforpython-6/gettingstarted.html).

## Планируемый запуск при разработке

После создания проекта в T01 договориться о точке входа `ritm` и проверить следующие команды:

```sh
uv sync --locked
uv run ritm
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

На момент написания эти команды ещё не запускают приложение: отсутствуют манифест, lock-файл и код. При первоначальном формировании зависимостей агент сначала создаёт и проверяет lock-файл. Затем `--locked` обеспечивает соответствие зафиксированному набору.

Обычный цикл: изменить Python/QML → выполнить подходящие проверки → запустить интерфейс → сохранить результат. Релизная компиляция при каждом изменении не требуется. Для QML дополнительно настроить проверку инструментами установленной версии PySide6 и записать фактические команды.

У ресурсов должен быть путь, работающий из любого текущего каталога. Разработка и тесты используют отдельные профили, чтобы эксперименты не меняли личные задачи.

Источник: [uv: Working on projects](https://docs.astral.sh/uv/guides/projects/).

## Планируемая упаковка

Первый кандидат — `pyside6-deploy` с Nuitka. Режим **standalone задавать явно**, поскольку настройки по умолчанию зависят от версии инструмента.

Результат: папка с исполняемым файлом, Python runtime, Qt-библиотеками/плагинами, QML, изображениями и прочими зависимостями. На другом компьютере распространяется вся папка, а не один исполняемый файл из неё. Отдельный установленный Python пользователю не нужен, но остаются требования к ОС, архитектуре и системным библиотекам.

Nuitka компилирует Python-код, сохраняя зависимость от среды выполнения Python/libpython. Это не превращает всё приложение в программу без Python runtime.

После T02 сохранить `pysidedeploy.spec` с явным режимом и включением нужных QML/ресурсов. Планируемая команда после проверки конфигурации:

```sh
uv run pyside6-deploy -c pysidedeploy.spec
```

Точный путь входного файла и спецификация определяются реальным проектом. `uv build` создаёт Python-дистрибутив и сам по себе не заменяет упаковку десктопной программы.

В Linux для упаковки могут потребоваться readelf, patchelf, заголовки Python и компилятор. Часть устанавливается инструментами в окружение; необходимость системных пакетов проверять по фактической диагностике. При Windows-сборке проверить поддерживаемый компилятор и средства анализа DLL. Вручную заранее устанавливать полный набор SDK на Linux не требуется.

Источники: [pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html), [Nuitka: User Manual](https://nuitka.net/user-documentation/user-manual.html).

## Форматы выпуска

Предложение для первого проверяемого артефакта — standalone-папка Linux в архиве. После её проверки выбрать удобную оболочку: например, AppImage для Linux и установщик/portable-папку для Windows. Выбор формата ещё не является доказательством переносимости.

Сборки готовить отдельно в соответствующей ОС и для целевой архитектуры: Linux-артефакт не заменяет Windows-артефакт. Сначала проверить минимальную упаковку, потом полный состав. Зависимости Linux могут требовать сборки на достаточно старой поддерживаемой базе; обещание «на любом Linux» не давать.

## Проверка релиза

- Запустить в чистом поддерживаемом окружении без средств разработки и исходников.
- Проверить ресурсы, Qt-плагины и запись данных в пользовательский профиль.
- Пройти сценарии TESTING, включая вложения и восстановление копии.
- Зафиксировать точную ОС/архитектуру, формат, версию, ограничения и контрольную сумму артефакта.
- Перед публичным распространением выбрать лицензию проекта и проверить требования реально используемых зависимостей. Публикация согласуется отдельно.

API-ключ поставляется самим пользователем в настройках. Без ключа локальные задачи, календарь, таймер и обычные реакции компаньона работают.
