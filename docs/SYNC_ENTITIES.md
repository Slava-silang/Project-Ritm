# Формат сущностей синхронизации v1 — T41b1

Реализован только чистый кодек `src/ritm/integrations/sync_codec.py`.
Он не подключён к приложению, сети или пользовательской базе.
Общий протокол и согласованные ограничения — [SYNC_PROTOCOL.md](SYNC_PROTOCOL.md).

## Контракт

`encode_entity(record)` возвращает детерминированный компактный UTF-8 JSON;
`decode_entity(bytes | str)` возвращает проверенную запись. Конструкторы записей
сами не заменяют проверку: граница проверки — эти две функции.
Оболочка содержит ровно `version: 1`, `kind`, `data`. Неизвестные, отсутствующие
и повторяющиеся ключи отвергаются на всех уровнях. Лимит одной записи — 2 МиБ;
превышение вызывает ошибку, данные не обрезаются. Лимиты пакетов — следующий шаг.

| kind | Поля data |
| --- | --- |
| task | id, title, completed, description, category_id, difficulty, expected_us, deadline, subtasks, completed_at |
| category | id, title |
| block | id, task_id, title, starts_at, ends_at, archived_task_title |
| removed | entity_kind, entity_id, root_id, revision, delete_epoch, reason |

UUID — канонические строки в нижнем регистре. completed — строго boolean;
сложность — целое 1–10 либо null. Заголовки непустые, без краевых пробелов.
Подзадачи первого уровня: id, title, completed, weight, items;
второго: id, title, completed. Проверяются уникальность ID и согласованность
завершения дерева. Веса — строки с двумя десятичными знаками, 0–100, сумма 100.
Все веса null означают автоматическое распределение; смешанный режим запрещён.
Кодек не пересчитывает веса и не исправляет состояния молча.

expected_us — положительное число микросекунд строкой либо null. revision —
положительное целое строкой, delete_epoch — неотрицательное целое строкой.
Все эти числа ограничены 2^63−1, без потери точности JavaScript. JSON float,
NaN/Infinity запрещены. Даты требуют часовой пояс и секунды; до 6 знаков
микросекунд. Выход нормализован в UTC с 6 знаками, сохраняет момент времени.
Неизвестный completed_at остаётся null; ненулевая дата допустима лишь у
завершённой задачи. category_id, deadline и expected_us допускают null.

Календарь: самостоятельное событие имеет task_id=null и непустой title;
блок задачи — task_id и пустой title. archived_task_title допускается только
для связанного блока как минимальная подпись вытесненной задачи.
Проверяется ends_at > starts_at.

Удаление: entity_kind — task/node/block/category; node требует root_id,
отличный от entity_id, остальные требуют root_id=null. reason — user_deleted
или retention; retention допустим только для task/block. В записи удаления
нет места для текста, снимков корзины, вложений или старого payload.

## Границы ответственности

Синтетические примеры — `tests/fixtures/sync/v1/`. Они проверяются побайтовым
обратным преобразованием и отдельными утверждениями о времени/числах/полях.
Ошибки SyncCodecError содержат фиксированное сообщение и kind, без входного текста.

Кодек не проверяет владельца, существование связанных задач/категорий, не
реализует вход, квитанции, курсор, разрешение конфликтов или хранение 50/30.
Выбор только живых задач из базы принадлежит будущему слою проекции: Task,
намеренно извлечённый из корзины, структурно неотличим от обычного Task.
Белый список полей не удаляет личные сведения из написанного пользователем
описания. Файлы, корзина, токены и источники почты не являются полями контракта.
Реальное применение данных и проверка изоляции пользователей ещё впереди.
