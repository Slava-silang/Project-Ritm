# Gmail: границы подключения и реализация T37

Исследовано 16 ноября 2026 года. T37a и T37b реализованы на подменах: модуль чтения, вход Google и отдельное окно источника. Передача писем модели и запись предложений ещё не подключены (T37c). Весь T37 остаётся в работе; реальная почта не читалась.

## Официальный способ

Использовать Gmail REST API v1 и OAuth настольного приложения. Нужны проект Google Cloud, включённый Gmail API, экран согласия и клиент типа Desktop app. Вход — в системном браузере, PKCE S256 и одноразовый state; возврат на случайный порт 127.0.0.1. Встроенный браузер и устаревший ручной перенос кода не использовать. Это отдельная авторизация, не часть входа ChatGPT. [OAuth для Desktop apps](https://developers.google.com/identity/protocols/oauth2/native-app).

Минимальное разрешение для текста писем — `https://www.googleapis.com/auth/gmail.readonly`. `gmail.metadata` не даёт тела и поиска q; `gmail.modify`/отправка/полный доступ не нужны. Readonly относится к restricted scopes. Для публичного распространения нужно отдельно проверить требования верификации и оценки безопасности; личный/тестовый режим имеет исключения, которые не означают разрешения публичного выпуска. [Разрешения Gmail](https://developers.google.com/workspace/gmail/api/auth/scopes), [верификация](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification).

Внешнее приложение в статусе Testing с Gmail scopes обычно получает refresh token на семь дней. Это ограничение Google следует объяснить в интерфейсе повторного входа. Клиент Google ещё не зарегистрирован средствами проекта, проверка аккаунта не выполнялась. [Сроки refresh token](https://developers.google.com/identity/protocols/oauth2#expiration).

MCP не обязателен: конкретный read-only адаптер закрывает текущую потребность. Универсальный доступ модели к почтовым инструментам не добавляется.

## Модуль чтения T37a

`integrations/gmail.py` не зависит от Qt, SQLite, профиля, ChatGPT и хранилища токенов. GmailController вызывает его в worker и принимает результат только пока запрос актуален. Никаких действий при импорте/старте приложения.

- `MailScope()` выбирает все UNREAD, включая спам/корзину Gmail; пользовательский q сужает охват, отдельный флаг может исключить спам/корзину. Обязательный label UNREAD не отменяется оператором OR в q. Календарь/корзина «Ритма» к этому флагу отношения не имеют.
- `GmailReader.read(token, scope, cancelled)` получает аккаунт через getProfile, собирает все страницы messages.list, удаляет повторные ID, затем получает каждое письмо messages.get(format=full). Нет изменения меток, отметки прочтения, отправки и загрузки вложений. [List](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list), [Get](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/get), [Profile](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users/getProfile).
- Снимок не атомарен на стороне Gmail: письмо может исчезнуть/стать прочитанным/попасть в исключённый спам между запросами. Такие записи подсчитываются в unavailable. При другой ошибке результат целиком отклоняется. Нельзя выдавать недочитанный набор за полный.
- До 500 уникальных писем, 100 страниц, 60 000 символов тела одного письма, 1 МиБ суммарного UTF-8 текста/основных заголовков. Превышение — ошибка с просьбой сузить охват, без скрытой обрезки. HTTP-ответ до 4 МиБ, timeout чтения 5 с, проверяемые сроки ответа 15 с/операции 180 с; блокирующий read может завершиться позже срока до своего timeout. Сигнал отмены проверяется до/после запросов и между чтениями.
- Текст plain предпочтительнее HTML-альтернативы. HTML преобразуется в текст без браузера, картинок, JavaScript, внешних ссылок-загрузок. MIME ограничен 20 уровнями/200 обработанными частями. Именованные вложения, Content-Disposition: attachment, изображения и другие бинарные части пропускаются. Текст с attachmentId автоматически не скачивается; body_available=False сообщает об отсутствии текста. Snippet не подставляется вместо полного тела.
- Транспорт допускает только GET к фиксированному gmail.googleapis.com и путям profile/messages/messages/ID. Redirect запрещён. Bearer не попадает в URL, безопасные ошибки не содержат HTTP body/адресов/токенов. Автоматических повторов нет.

Идентичность источника — хеш аккаунта плюс неизменный ID письма. Это разделяет аккаунты, но не делает ключ анонимными данными. Fingerprint включает содержимое, исключает historyId/метки: изменение прочтения не означает новую задачу. [Модель Message](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages).

source_url — формируемая ссылка веб-интерфейса Gmail с указанием аккаунта и ID; её реальное открытие ещё не проверено. Текст писем/токены никуда не сохраняются этим модулем; Mail исключает содержимое и адреса из repr. Ключи и fingerprint пока не используются как готовая защита записи от дубликатов — она относится к T37c.

## Подключение и просмотр T37b

В помощнике нажать «Источники — Gmail». Нужна собственная конфигурация Google: включить Gmail API в проекте Google Cloud, настроить согласие с gmail.readonly и тестового пользователя, создать OAuth client типа Desktop app, скачать JSON **вне репозитория**. Регистрация проекта/изменение его настроек в этом этапе не выполнялись. Данные Google не нужно вводить в чат с моделью.

«Загрузить конфигурацию Google» открывает обычный выбор файла. Проверяются installed/client_id/client_secret и адреса Google, Web client/чужие адреса отклоняются. Официальный старый auth_uri /o/oauth2/auth и старый token_uri из скачанных конфигураций принимаются, но фактические запросы всегда идут к фиксированным современным адресам. [Формат JSON Google](https://googleapis.github.io/google-api-python-client/docs/client-secrets.html). Исходный файл остаётся на месте, приложение не копирует его в профиль. При подключённом аккаунте для смены конфигурации сначала удалить прежнее подключение.

«Войти через Google» запускает системный браузер с отдельным разрешением gmail.readonly. PKCE S256/state и loopback 127.0.0.1; отказ браузера/Google, отмена и время ожидания не дают успешного входа. Узнать адрес через getProfile можно после разрешения; письма при входе не читаются. Адрес берётся из ответа Gmail, а не из непроверенного ID token.

«Открыть сохранённое подключение» читает только локальное защищённое хранилище: без старта браузера, автоматического refresh или чтения писем. На запуске приложения эта операция не вызывается. Для чтения нужно отдельно разрешить выбранный охват и нажать «Прочитать письма»; согласие сбрасывается при новом действии/изменении фильтра и закрытии окна. Просмотр plain text, тело выбранного письма; HTML из заголовков/текста не выполняется. Недоступные записи подсчитываются. Фильтр в этой версии не сохраняется на диск.

Конфигурация и токены — отдельный сервис ProjectRitm.Gmail существующего защищённого Secret Service, ключ привязан к профилю. Никакого plaintext keyring или создания/разблокировки системной коллекции. При отказе записи новый вход только в памяти с предупреждением: ранее сохранённый вход может остаться прежним. Успешное удаление подключения убирает и конфигурацию, и токены локально, не отзывает разрешение Google на сервере. Отказ защищённого удаления не выдаётся за успех. Исходный скачанный JSON пользователь удаляет отдельно.

Refresh выполняется только при явном чтении, когда access token истекает; refresh token сохраняется при ответе без нового. Отказ 400/401 при refresh убирает недействительный вход, требует повторного входа. На сетевой ошибке нет скрытых повторов. Endpoint обмена фиксирован oauth2.googleapis.com/token, POST form; redirect запрещён, токены/код/секрет не выводятся в ошибках и не попадают в URL.

Закрытие окна/отмена очищают письма из контроллера, поздний ответ не возвращает их в UI. Письма/адрес источника/ключи входа не пишутся в историю помощника, SQLite или backup. Во время запроса временные значения остаются в worker до завершения; стирание байтов памяти не обещается. Новых файлов профиля и схемы БД нет. В .gitignore добавлены типичные client_secret*.json/gmail-client*.json/gmail-tokens*.json; произвольный исходный JSON всё равно хранить вне репозитория.

## Следующий ограниченный шаг

T37c: явный выбор писем и согласие на передачу выбранной модели, строгие черновики задач/событий/обновлений, редактирование и ручное подтверждение. Связь с источником и квитанция применяются атомарно с записью задачи/события; повтор, параллельная правка, корзина/удаление и перезапуск не должны создавать дубликаты. Письмо — данные, не дополнительные инструкции или полномочия модели.

Уточнение пользователя: изменение из письма для уже выполненной задачи показывается, но сохраняет статус «выполнено»; запись только после подтверждения. Не открывать выполненную задачу из-за добавления новой невыполненной ветки — при проектировании предложения учитывать общие каскадные правила. Это требование пока не реализовано.

Перед реальной передачей писем провайдеру проверить условия обработки данных конкретного подключения, раскрытие получателя и согласие пользователя. Требования Google к использованию/передаче данных действуют и при внешней модели; наличие OAuth-разрешения само по себе не решает этот вопрос. Публичная поставка и регистрация Cloud-проекта отдельно. [Google Workspace user data policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy).
