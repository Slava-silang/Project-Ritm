# Подключение ChatGPT — T23

Реализация готова к проверке. Реальная доступность входа и запросов для аккаунта пока не подтверждена; T23 остаётся in_progress. Автотесты используют подменный OpenAI, браузер и защищённое хранилище. Они не подтверждают допуск настоящего аккаунта или успешную работу сервера OpenAI.

## Проверка пользователем

1. Запустите текущие исходники: `uv run --locked ritm`. Старая самостоятельная сборка T02 не содержит этой функции.
2. Откройте «Помощник (тест)» → «Подключение ChatGPT» → **Continue with ChatGPT**. В браузере выберите свой аккаунт/рабочую область и разрешения для «Ритма». Пароль и коды не нужно вводить в приложение или отправлять в чат.
3. После возврата проверьте аккаунт и разрешение использования подписки. Нажмите «Загрузить доступные модели». GPT-6.1 Sol выбирается, если присутствует в каталоге. Если его нет, другую модель нужно выбрать явно.
4. Для проверки включите «Разрешаю тестовый запрос…» и нажмите «Проверить запрос по подписке». Этот запрос расходует доступный лимит, но не передаёт ваши задачи. Успех подтверждается только завершённым ответом. Вход и список моделей сами по себе не подтверждают доступ к запросам.
5. Для обычных запросов нажмите «Использовать ChatGPT». Запрос и выбранная задача отправляются только действием пользователя; остальные задачи и файлы автоматически не включаются. Результат по-прежнему проверяется и сохраняется после подтверждения.
6. «Локальный тест без сети» возвращает подменный адаптер. «Выйти из аккаунта» очищает токены. После перезапуска «Восстановить сохранённый вход» читает защищённое хранилище; загрузка каталога моделей выполняется отдельной кнопкой.

При отказе входа или запроса сообщите этап и текст ошибки в интерфейсе. Не отправляйте токены, OAuth-ссылку возврата, пароль или содержимое системного хранилища.

## Что и где хранится

На Linux используются только Secret Service через keyring и отдельная запись ProjectRitm.ChatGPT на профиль. Учётные данные не передаются в QML. При недоступности или блокировке хранилища они остаются в памяти с пояснением. Приложение не открывает системный диалог разблокировки и не создаёт новую коллекцию: разблокируйте существующее хранилище средствами ОС и выполните вход заново, если нужно сохранить его. Сохранённая регистрация переживает выход, чтобы повторный вход использовал тот же выданный client ID. Её файл `chatgpt-registration.json` в профиле содержит только случайный host ID и выданный client ID, без токенов. В архив задач он не входит. Вход в аккаунт при запуске не восстанавливается автоматически; сетевых запросов на старте нет.

Токены, запросы и ответы в журналы не записываются. История диалога ещё не реализована (T24). После переноса профиля на другое устройство следует выполнить новый вход: защищённая запись привязана к этому профилю на устройстве.

## Границы текущей реализации

Одна активная регистрация аккаунта. Повторный вход использует сохранённый client ID; выбор нескольких аккаунтов относится к следующему интерфейсу. Необязательный вход с платным API-ключом пока не добавлен. Автоматического переключения на API нет. При лимитах приложение показывает сообщение, не записывает неполный ответ и не повторяет запрос автоматически. Текст запроса остаётся в открытом окне для ручного повтора; история между запусками — T24.

Реальный Secret Service с пользовательскими токенами, настоящий браузерный вход и inference ещё не проверены. Windows, Wayland и новая самостоятельная поставка также не проверены. На платформах без Secret Service действует режим памяти.

## Официальные основания (проверено 13 ноября 2026)

- [Обзор Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source): схема для локальных приложений и постоянный идентификатор установки.
- [Пример локального приложения](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt): динамическая регистрация, loopback, PKCE, проверка идентичности и отдельное подтверждение права использования подписки. Допуск личного локального проекта не означает допуск конкретного аккаунта.
- [Модели и запросы](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference): каталог выбранного аккаунта и публичный Responses endpoint, завершение стрима.
- [Ограничения](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [ошибки](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery): допустимые параметры и отсутствие автоматического другого способа оплаты.

Авторизационные endpoint и ключи подписи приложение получает через HTTPS OIDC discovery для фиксированного issuer auth.openai.com; произвольные origin и перенаправления с Bearer-токеном запрещены. Недоступные через просмотр документации отдельные страницы регистрации/сессий не подменялись догадками: использованы доступный официальный пример, OIDC discovery и подменные проверки; реальный протокол требуется подтвердить пользовательской проверкой выше.
