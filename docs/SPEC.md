# «Ритм»: согласованные требования

Дата фиксации: 8 ноября 2026 года. Источник — ответы пользователя в чате подготовки проекта.

## S01. Назначение и выпуск

Студенческий десктопный проект, которым автор планирует пользоваться после сдачи. Единственное названное требование преподавателей — выполнение проекта с помощью ИИ. Функции README являются пожеланиями автора.

Главный сценарий: получить лабораторную, указать сложность и ожидаемое время, разбить на задания и мелкие пункты, назначить дедлайн и отслеживать выполнение.

Приоритеты: текущие задачи, подзадачи, контроль дедлайнов, сохранность данных. Ориентир подготовки учебной работы — около 20 дней от 8 ноября, примерно 28 ноября 2026 года. Это ориентир, а не обещание закончить весь объём к точной дате.

Целевой учебный выпуск: задачи, календарь, фокусировка, статистика, вложения, резервные копии, ИИ-помощник, текстовые навыки и компаньон с временной графикой. При нехватке времени перенос функций согласуется с пользователем.

Согласованный стек: Python + PySide6 + QML + SQLite; Electron исключён. Первая проверяемая версия — Linux. Сохраняется возможность выпуска Windows-версии. Доступ к Windows и целевая версия Windows пока не уточнены; её работоспособность нельзя объявлять без проверки.

## S02. Задача и уровни вложенности

- Главная задача: название, описание, необязательная категория, сложность 1–10, ожидаемая длительность, необязательный дедлайн с датой и точным временем.
- Обязательно только название. Незаданная сложность и длительность отличаются от нуля.
- Сложность и ожидаемое время задаются только главной задаче, независимо друг от друга. Дополнительное влияние сложности на планирование и прогресс пока не определено.
- Подзадачи первого уровня имеют название, отметку выполнения и вес.
- Подзадачи второго уровня имеют название и отметку выполнения, собственного веса у них нет.
- Более глубокая вложенность отсутствует. Собственных дедлайнов у подзадач нет: используется срок главной задачи.
- Категории создаёт и называет пользователь; у задачи не более одной категории.

## S02a. Регулярные задачи — уточнение 26 ноября

- При создании/изменении можно включить регулярность, задать интервал N календарных дней (1–36500) и первый день в формате ГГГГ-ММ-ДД. Дата считается в местном календаре компьютера, а не как N × 24 часа. Обычные задачи не меняются.
- По ответам пользователя: расписание фиксированное от первого дня, выполнение его не сдвигает; при следующем сроке пропущенный экземпляр заменяется актуальным. Просрочка не начисляется: у регулярного экземпляра нет дедлайна. После долгого отсутствия появляется лишь последний наступивший повтор, без накопления всех пропусков.
- Выполненные экземпляры остаются в истории с отдельными ID/датами завершения. Новый экземпляр получает новые ID дерева и пустые отметки, сохраняя название/описание/категорию/сложность/ожидаемое время/подзадачи/веса предыдущего. Файлы, календарные блоки и фокус не копируются (это явно указано в форме), остаются у прежнего экземпляра.
- До первого дня задача скрыта из рабочего списка, но расписание доступно в «Параметры → Регулярные задачи». Там его можно изменить/отключить. Отключение оставляет текущую задачу обычной и видимой. Удаление текущей главной задачи останавливает расписание; восстановление из корзины не запускает его снова.
- Пропущенный экземпляр не помечается выполненным и не переносится в корзину. Его локальная запись сохраняется скрытой ради прежних файлов/календаря/фокуса. Выполненные повторы используют обычные правила наград; пропуски наград не дают.
- Для будущей синхронизации 26 ноября согласован единый часовой пояс аккаунта: при подключении взять пояс компьютера, сохранить, разрешить ручную смену; в поездках не переключать автоматически. Обычный локальный режим пока использует местную дату как раньше. История повтора хранит запланированный день отдельно от фактической даты выполнения.
- Обновление при запуске/обновлении списка/смене местной даты выполняется в worker и транзакции. Повтор запуска не создаёт дублей; откат часов не возвращает старый повтор. Это desktop-функция: формат записей уже учитывает расписание (T41b2a), но применение операций, межустройственный rollover и сам обмен ещё не подключены.

## S03. Выполнение и веса

- Первоначально подзадачам первого уровня назначаются равные веса. Пользователь может изменить их; сумма составляет 100%.
- Подзадача первого уровня с вложенными пунктами завершена, когда выполнены все её пункты. До этого её вес в прогресс главной задачи не начисляется.
- Подзадача первого уровня без вложенных пунктов завершается вручную.
- Отметка выполнения родителя завершает всех его потомков, включая оба уровня при завершении главной задачи.
- Снятие отметки с родителя снимает отметки со всех его потомков.
- Снятие отметки с отдельного нижнего пункта открывает его родителей, сохраняя выполнение соседних пунктов.
- Главная задача с подзадачами завершается автоматически, когда завершены все её подзадачи первого уровня.
- Прогресс главной задачи — сумма весов завершённых подзадач первого уровня. Без подзадач прогресс равен 0% или 100% согласно ручной отметке.
- Добавление невыполненного пункта завершённому родителю возвращает родителя и необходимых предков в незавершённое состояние.
- При добавлении/удалении первого уровня веса пересчитываются с сохранением относительных пропорций существующих весов и возможностью ручного исправления.

Пример: «Расчёты» весят 40%, «Отчёт» — 60%. Пока хотя бы один пункт расчётов не завершён, расчёты дают 0%; завершение всех пунктов даёт 40%.

Техническая политика T07:

- Точность весов — 0,01 процентного пункта. Начальное распределение равное; сотые доли остатка выдаются методом наибольших остатков, при равенстве — по порядку подзадач. Например, три пункта получают 33,34 / 33,33 / 33,33%. Сумма всегда ровно 100%.
- Ручное изменение задаёт весь набор весов первого уровня по ID: значения от 0 до 100, не более двух значащих десятичных разрядов после запятой и сумма ровно 100. Неверная сумма отклоняется без сохранения. Есть явный сброс к равным весам.
- Нулевой вес допустим. Такая ветка не добавляет процент, но для завершения всей задачи требуется выполнить и её. Поэтому 100% веса могут быть набраны раньше завершения всех веток; статус выполнения определяется всеми подзадачами, а не сравнением прогресса с 100.
- При добавлении в список из n подзадач новая получает 100/(n+1)%, остальные совместно получают 100*n/(n+1)% пропорционально своим прежним весам. Переданный в новом пункте вес автоматически заменяется; ручное распределение применяется отдельной командой. После расчёта используется общее округление до сотых.
- При удалении веса оставшихся нормируются до 100% с сохранением пропорций до округления. Если остались только нулевые веса, они распределяются поровну. Удаление последнего пункта сохраняет текущую отметку главной задачи; она снова становится ручной.
- Добавление и последующее удаление пункта может изменить старые доли на сотую из-за округления; до округления пропорции сохраняются. При количестве более 10 000 пунктов часть равных весов будет нулевой из-за выбранной точности.
- Для исходного дерева без заданных весов используются равные доли. Частично заданные или несогласованные веса автоматически не исправляются: их нужно явно задать целиком либо сбросить к равным.

## S04. Список и карточка задачи

- Сверху — добавление задачи, поиск, фильтры.
- Группы активных задач: «Просроченные», «Предстоящие», «Без дедлайна».
- В первых двух группах сортировка по дедлайну от раннего к позднему. Просроченные выделяются цветом и текстовой подписью.
- В строке — название, дедлайн, прогресс; дерево подзадач раскрывается в списке.
- Выбранная задача открывается в панели справа. В узком окне подробности занимают основную область.
- Карточка содержит описание, сложность, ожидаемое время и редактирование подзадач.
- Завершённые главные задачи доступны через отдельный фильтр «Выполненные» и могут быть возвращены в работу.
- Поиск без учёта регистра проверяет название, описание и названия обоих уровней подзадач. Поиск, категория и состояние выполнения действуют одновременно; по умолчанию показаны активные, также доступны выполненные и все задачи.
- Просрочка наступает строго после момента срока: при равенстве текущего времени и срока задача ещё предстоящая. Моменты сравниваются с учётом часового пояса; открытый список обновляет группы автоматически, без уведомлений.
- В узкой карточке фильтры скрыты; кнопка «К списку» возвращает список с поиском и фильтрами.
- Напоминания и уведомления о дедлайнах отсутствуют.

## S05. Календарь

- Виды «Неделя» и «Месяц», кнопка «Сегодня»; первоначально открывается неделя. Неделя начинается в понедельник; месячная сетка включает полные недели с соседними днями. Есть переходы назад/вперёд и выбор дня со списком событий.
- В широком недельном виде события размещены по дням; в месяце и узком виде видны счётчики, подробности — в выбранном дне. Рабочие блоки, самостоятельные события и дедлайны различаются цветом и обозначением. Клик блока/дедлайна открывает задачу; клик самостоятельного события — его редактирование.
- Ручное создание доступно из календаря и карточки задачи. Поля начала/окончания задаются в формате ДД.ММ.ГГГГ ЧЧ:ММ; для неоднозначного часа можно явно добавить смещение. Ошибка сохраняет форму, отмена не создаёт блок.
- Переходящий через полночь блок показан частями по дням, сохраняя один ID и единую плановую длительность. При наступлении нового дня отметка «Сегодня» обновляется без смены просматриваемого периода.
- Дедлайн показан отдельной отметкой. Назначение дедлайна само по себе не создаёт рабочий блок.
- Рабочий блок: ссылка на главную задачу, дата, время начала и окончания. У задачи может быть несколько блоков.
- Самостоятельное событие (пара, прогулка и т. п.) создаётся через «+ В расписание» → «Событие»: обязательны название, начало и окончание. Задача для него не нужна, в том числе при пустом списке задач. События показаны фиолетовым, допускают переименование, перенос и изменение длительности по тем же правилам. Они участвуют в предупреждениях о пересечении, но не имеют дедлайна/прогресса и не входят в запланированное время задач. Корзина задач на них не влияет.
- Создание блока вручную, перенос мышью и изменение длительности. Ручка ↔ переносит блок между днями, сохраняя местное время начала и фактическую длительность. Перенос дневной части ночного блока сдвигает весь блок на разницу дат.
- На шкале выбранного дня тело блока сдвигает время, нижний край меняет длительность; шаг — 15 фактических минут. Шкала учитывает 23/25-часовые дни и подписывает повторяющиеся часы со смещением. Ночной блок переносят на шкале за начальную часть, растягивают за конечную; точная форма ⋯ доступна всегда.
- Escape отменяет жест. При ошибке записи показано сообщение, предпросмотр возвращается к подтверждённому состоянию. Если блок изменён в другом окне, устаревшее изменение отклоняется с предложением обновить календарь.
- ID блока и главная задача сохраняются при редактировании; дедлайн и выполнение задачи не меняются.
- Пересечения допустимы, но сопровождаются предупреждением.
- T33/I34: в выборе для нового рабочего блока доступны только незавершённые задачи. Существующие блоки выполненных задач сохраняются и редактируются с прежним владельцем. Завершение выбранной задачи при открытой форме сбрасывает её выбор и требует выбрать активную задачу; независимые события доступны и без активных задач.
- Дедлайн редактируется отдельно. Его перенос сохраняет даты блоков; блоки после срока получают предупреждение.
- Карточка показывает ожидаемую длительность и сумму запланированного времени. Они могут различаться.
- Техническая политика T10: интервал — [начало, конец), конец строго позже начала. Соприкасающиеся блоки не пересекаются; частичное и полное наложение разрешены с предупреждением, в том числе между разными задачами.
- Сумма запланированного времени складывает длительности всех блоков, включая каждый из пересекающихся. Предупреждение о сроке появляется, если хотя бы часть блока находится после дедлайна (конец строго позже срока); окончание ровно в срок допустимо. Отсутствие дедлайна отключает только предупреждение о сроке.
- Моменты блоков хранятся в UTC с точностью до микросекунд, отображаются в местном времени. Длительность — фактически прошедшее время между моментами, включая перевод часов. Несуществующее местное время отклоняется, повторяющийся час различается по смещению/fold.
- Перенос задачи в корзину скрывает её блоки из календаря, но сохраняет их; восстановление возвращает прежние ID, даты и длительности. При удалении подзадачи блоки главной задачи сохраняются. Повторное создание другой главной задачи с ID удалённой запрещено.
- Завершение календарного интервала само по себе не меняет выполнение задачи.
- Нужны редактируемые часы работы для предложений ИИ. Конкретные начальные часы выбираются как техническое значение по умолчанию и явно показываются пользователю.

## S06. Фокусировка

- Сессия привязана к главной задаче. Можно указать плановую длительность либо запустить секундомер.
- После заданной длительности предлагается завершить сессию или продолжить; дальнейшее время учитывается при продолжении.
- Управление: начать, пауза, продолжить, завершить. Одновременно активна не более чем одна сессия.
- Начало другой сессии предлагает завершить текущую. Паузы исключаются из рабочего времени.
- История сессий находится у главной задачи. Длительность можно исправить; пропущенную запись можно добавить вручную.
- Ожидаемое, запланированное и фактически затраченное время показываются отдельно. Время не начисляет проценты выполнения.
- T34a: настройка «Приостанавливать таймер при сне и блокировке» по умолчанию выключена, в том числе для прежних профилей без этой настройки. При выключении время сна/блокировки учитывается как работа вне компьютера. При включении сессия ставится на паузу, продолжение вручную. Ручная пауза не снимается автоматически при любом значении настройки.
- Выход из приложения при активной сессии предлагает её завершить.
- После сбоя незавершённая сессия восстанавливается через проверку пользователем времени окончания.
- Правила Pomodoro определены в T34 / S16. Анализ активных программ, автоматическая оценка внимания и блокировка сайтов остаются отложенными.

## S07. Недельный прогресс и статистика

- Неделя — понедельник–воскресенье по местному времени компьютера.
- В недельный расчёт входят главные задачи с дедлайном в этой неделе, включая завершённые. Задачи без срока и просроченные с прошлых недель в эту полосу не входят.
- Недельный прогресс — среднее арифметическое прогрессов включённых главных задач. Их сложность и длительность весами не являются.
- Пример: 100%, 50%, 0% дают 50% недели. Рядом указывается число задач в расчёте.
- Добавление задачи и перенос дедлайна пересчитывают показатель. Пустая неделя показывает пояснение, без деления на ноль.
- Отображаются недельный прогресс, число завершённых задач, число текущих просроченных, время фокусировки по дням, ожидаемое и фактическое время по задаче.
- Период счётчика завершённых задач должен быть подписан. По умолчанию для недельного обзора — завершённые за выбранную неделю; текущие просроченные считаются на текущий момент.
- Достижения и декоративный сад согласованы как расширение T39 (S16); модель и отдельное хранилище T39b реализованы без интерфейса/начислений. Серии дней отдельно не согласованы.

## S08. Локальные данные, файлы и корзина

- Основные функции работают локально без интернета, аккаунта и облачной синхронизации.
- Вложения разрешены у главной задачи и обоих уровней подзадач.
- Файл копируется в управляемую приложением папку; исходный файл остаётся на месте. Перемещение исходного файла не нарушает вложение.
- Вкладка «Материалы» хранит книги и другие файлы без привязки к задаче. В диалоге вложений любого уровня можно прикрепить ссылку на материал. Несколько ссылок открывают одну сохранённую копию.
- Перенос задачи или пункта в корзину скрывает его ссылки и сохраняет материалы в библиотеке. Окончательная очистка задачи удаляет её ссылки, сохраняя общую копию.
- Открытие — внешней программой. Встроенное чтение книг отложено.
- Удалённая главная задача или подзадача любого уровня попадает в корзину с поддеревом и возможностью восстановления. Удаление подтверждается в интерфейсе; восстановление доступно и после перезапуска.
- При удалении первого уровня веса оставшихся пересчитываются по S03. При удалении нижнего пункта выполнение предков пересчитывается; после удаления последнего нижнего пункта подзадача сохраняет свою отметку и становится ручной.
- Восстановление возвращает UUID, содержимое и отметки выбранной ветки, сохраняя последующие изменения других пунктов. Для первого уровня прежние веса возвращаются точно, если состав и веса оставшихся пунктов не менялись. Иначе восстановленный пункт добавляется с новой автоматической долей по S03. Родителя нужно восстановить перед отдельно удалённым потомком; при конфликте ID запись остаётся в корзине.
- Восстановление возвращает копии вложений и ссылки выбранной ветки. Для главной задачи возвращаются также календарные блоки и завершённые фокус-сессии.
- Окончательная очистка применяется только к выбранным и подтверждённым записям. Если потомки лежат в корзине отдельно, их нужно выбрать вместе с родителем. Активную сессию задачи нужно завершить или восстановить перед очисткой.
- При окончательном удалении главной задачи удаляются её рабочие блоки, история фокуса и даты завершения. При удалении подзадачи удаляются вложения и ссылки её ветки. Исходные файлы, независимые события и общая библиотека сохраняются.
- Если копию временно не удаётся удалить, приложение показывает число оставшихся файлов и позволяет повторить очистку.
- Пользовательские данные хранятся отдельно от программы и каталога сборки.

Остаток — ожидаемая длительность минус сумма всех уже запланированных блоков этой задачи, не меньше нуля; фактический фокус и проценты выполнения из этой оценки автоматически не вычитаются.

Провайдер получает выбранную задачу, пожелания, рабочие часы и интервалы периода без названий других задач/событий. Вложения и прежние обсуждения здесь автоматически не отправляются.

До подтверждения можно исправить даты/время или убрать блок. Нераспределённое время показано отдельно; допускается подтверждение посильной части. При пустом свободном времени или нулевом остатке внешний запрос не выполняется.
- Весь набор применяется одной транзакцией с защитой от повторного подтверждения. Изменение задачи, занятости периода, уже запланированного времени или рабочих часов требует нового предложения; прошедшее начало блока также отклоняется. Предложение живёт до закрытия окна и не восстанавливается/не применяется после перезапуска автоматически.

Прошлые диалоги передаются только после явного выбора продолжения; при смене режима, задачи или подключения обсуждение начинается заново. Для планирования также занятость нужного периода и настройки рабочего времени. Прочие материалы пользователь добавляет явно.

- T26: локальный текстовый режим TXT/Markdown/PDF. T35 расширяет вход изображениями и документами по правилам S16 и MEDIA_INPUTS.md; отдельного местного OCR нет.

- При ошибке — понятное сообщение и возможность повторить. Повторные запросы и повторное подтверждение сохраняют результат однократно.

## S11. Учётные данные, история, навыки

- Токены входа и необязательные API-ключи сохраняются в защищённом системном хранилище, исключаются из журналов и резервных копий. Выход из аккаунта очищает сохранённые данные авторизации этого подключения.

Сохраняются запросы, проверенные предложения и статусы; исходные файлы и учётные данные в историю не добавляются. История не входит в резервную копию задач.

- T27: библиотека доступна в окне помощника и окне расписания. Можно создать навык, отредактировать сохранённый и явно выбрать один либо «Без навыка». Сохранение само по себе навык не включает. Выбор общий для этих окон на текущий запуск; после перезапуска исходно «Без навыка».
- Название обязательно (до 120 символов), описание необязательно (до 1000), инструкция обязательна (до 12000). До 100 навыков/1 МиБ в локальном skills.json отдельно от базы и копий задач. Повреждённая библиотека не перезаписывается автоматически. Устаревшая правка требует обновления списка.
- В запрос входит только выбранный навык как пользовательские пожелания к содержанию; формат, допустимые действия, файловый контекст и подтверждение определяет приложение. Текст навыка не исполняется и не разрешает читать перечисленные в нём файлы. Он доступен для просмотра через редактор до запроса.
- Выбор/отключение/редактирование выбранного навыка сбрасывает текущее предложение и обсуждение; изменение невыбранного навыка их не меняет. Отпечаток выбранной версии включён в границу диалога: продолжение старой истории требует того же навыка с тем же содержимым. Во время запроса/сохранения изменения навыка в этом окне недоступны.
- В журнале видно название применённого навыка. Инструкция библиотеки отдельно в сообщения не дублируется; ответы модели могут содержать её цитаты. Удаление навыков и импорт исполняемых пакетов в T27 не входят.
- Файлы и внешние материалы рассматриваются как данные. Они не могут расширять полномочия помощника своими инструкциями.

### Pomodoro — T34

- Исходно работа 25 минут, короткий перерыв 5 минут, длинный 15 минут после четырёх рабочих интервалов; длительности настраиваются.
- Переходы ручные. После окончания работы время до «Начать перерыв» продолжает учитываться как работа над текущей задачей. После конца перерыва работа начинается только кнопкой «Начать работу».
- Перерыв — отдельный таймер, не рабочее время. Цикл общий при смене задач; фактическая работа остаётся привязана к соответствующей задаче по S06.
- Окончание показывается внутри приложения и репликой компаньона, если он включён. Звуки и системные уведомления в этот объём не входят. Обычные предложения перерыва компаньоном во время Pomodoro отключены.
- Сон/блокировка следуют настройке S06: при выключенной автопаузе рабочий интервал/перерыв продолжается, при включённой — приостанавливается с ручным продолжением. Переходы этапов всегда ручные; пропущенное во сне окончание показывается после пробуждения. Остановка приложения сохраняет этап/остаток, продолжение после запуска вручную. При сбое фактическое время проверяется по правилам восстановления S06.
- T34: длительности 1–240 минут, настраиваются до запуска цикла и сохраняются. Во время цикла смена задачи сохраняет общий прогресс интервала; отдельная плановая длительность фокуса не используется. «Завершить цикл» с подтверждением сохраняет работу, сбрасывает счётчик/этап и оставляет настройки.
- Остаток перерыва после аварии восстанавливается по последнему успешному checkpoint (обычно раз в 5 секунд; при занятости/ошибке записи интервал больше), без времени отсутствия приложения. При обычном выходе сохраняется точная пауза. После окончания перерыва таймер останавливается, работа автоматически не начинается.

- Открытия: виды растений/деревьев, украшения, анимации, фоны/варианты поля. Известные заранее покупки/достижения/уровни сочетаются, часть достижений скрытая. Смена темы меняет палитру, не структуру и заработанное. Приняты сообщения без звука и отключаемые анимации, без обязательных серий посещений. Возврат часов назад не возвращает закрытый месяц и не даёт повторных наград.

### Синхронизация и Telegram Mini App — T41–T42

- Приложение локально без регистрации; синхронизация добровольна. Несколько изолированных пользователей. Регистрация/вход в Mini App через существующий Telegram-аккаунт без запроса телефона/email/пароля Telegram. Сервер сохраняет только необходимый Telegram ID, внутренние ID и данные доступа; имя/ник/фото/контакты/переписка не сохраняются.
- В Mini App выдаются индивидуальный случайный логин и пароль **Ритма** для входа с компьютера. Пароль можно регенерировать; он не хранится открытым, на сервере только защищённый хеш. Это заменяет первоначальный одноразовый код привязки. Предлагаемый безопасный режим регенерации — отзыв прежних desktop-сессий, новый вход новым паролем; точные TTL/параметры определяются при реализации по SYNC_PROTOCOL.md.
- Синхронизируются текущие задачи/подзадачи, календарь и категории. В облаке все активные и 50 последних завершённых главных задач (ordinary и прошлая occurrence-история суммарно). По уточнению 26 ноября текущие экземпляры действующих расписаний сохраняются отдельно вне этого лимита, даже выполненные. В облаке также прошедший календарь за 30 суток и будущие/текущие события. Локальная история не обрезается. Файлы/фокус/сад/валюта/история ИИ/навыки/локальные настройки/учётные данные подключений не синхронизируются. Общий часовой пояс расписаний — отдельная настройка аккаунта.
- Удалённое содержимое и корзина в облаке не хранятся. Удаление убирает задачу/пункт из Mini App; компьютер сохраняет свою локальную корзину и связанные файлы. Восстановление возможно из имеющейся локальной корзины отдельным явным действием. Сервер сохраняет маленькую служебную отметку без текста, чтобы старое устройство не вернуло удалённое. Очистка истории по лимиту не удаляет локальные задачи/календарь.
- Последнее принятое сервером обычное изменение побеждает отдельно для каждой главной задачи и календарного события/блока. Подзадача меняет всё дерево корня; независимые задачи не перезаписываются общей копией БД. Повтор операции не считается новым изменением; часы устройства не определяют победителя. Защита удаления/различие retention и user_deleted — SYNC_PROTOCOL.md.
- Локальная инфраструктура T41c1–T41c5c2a хранит UUID привязки, несетевые намерения и неизменяемые запросы с проверенными квитанциями. Это ещё не отправка или применение серверных данных.
- Создаваемые и импортируемые архивы исключают эту привязку/очередь; после восстановления требуется повторное подключение с предпросмотром. Рабочий исходный профиль при создании копии не очищается; аварийный rollback сохраняет его очередь. Storage API позволяет явно включить атомарную запись обычных задач в очередь; запуск/миграция её не включают. Переходы текущих/прошлых повторов, detach и восстановления дополнительно сохраняются как локальные факты, пока без подготовки к отправке (SYNC_REGULAR_CAPTURE.md). Read-only planner истории выбирает предложения только по явным известным основаниям/соответствиям UUID, без записи/отправки и удаления фактов (SYNC_HISTORY_PLAN.md). Planner текущего расписания готовит один следующий шаг на известном основании, canonical rollover и stop/delete без догадок о квитанциях (SYNC_REGULAR_PLAN.md). Compound resolver/сохранение команд/календарь/категории и отправка ещё не подключены (SYNC_CAPTURE.md).
- Desktop работает без сети, сохраняет очередь и передаёт изменения при восстановлении связи. Доступно получение из облака без стирания необработанных локальных правок. Первое объединение — резервная копия/предпросмотр и выбор при конфликтующих UUID; не безусловная замена профиля. Возвращённые из облака старые выполнения не дают повторных наград сада; учёт новых удалённых выполнений согласовать до inbound T41c.
- Mini App через бота работает с интернетом: создание/редактирование задач, подзадач, выполнения, сроков и календаря, выдача доступа/регенерация пароля/отзыв устройств. Материалы/ИИ и чтение сообщений Telegram не входят. Desktop не обязан быть включён для обращения Mini App к работающему серверу.
- Временный сервер — второй компьютер пользователя, потом переносимый отдельно. При отключении сервера облачные функции недоступны, desktop остаётся локальным. Размещение/публикация/настройка ОС/платежи требуют отдельного разрешения; серверный код — в отдельном закрытом репозитории.

Серверных резервных копий по явному выбору пользователя нет; локальные копии сохраняются. При утрате сервера восстанавливается только имеющееся локально; новый сервер не является приказом очистить профиль. Схема/открытые технические параметры — SYNC_PROTOCOL.md; код/реальная безопасность/размер сервера пока не проверены.
