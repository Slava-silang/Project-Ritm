# Предложения из писем: T37c1/T37c2

Ядро T37c1 реализовано 16 ноября; T37c2 подключает пользовательский поток 18 ноября 2026 года. Проверки используют временные профили и подменные Google/модель; реальная почта/модель не вызывались.

## Формат и границы

`SourceRef.from_mail(mail)` строится приложением из прочитанного письма, а не из ответа модели. Ключ — аккаунт+ID, fingerprint — содержание, URL — только Gmail с тем же аккаунтом/ID. Модель не может подменить source URL, fingerprint, аккаунт и права доступа. `SourceLink` хранит вид, UUID записи и ревизию связи.

`parse_mail_proposal(request_id, payload, source, link=None, before=None)` возвращает неизменяемый MailProposal. Один запрос — одно выбранное письмо и одна задача с подзадачами либо самостоятельное событие. Следующее письмо пользователь выбирает отдельно; автоматической пакетной обработки всей почты нет.

Создание задачи:

```json
{"kind":"task","task":{"title":"Подготовить лабораторную","difficulty":6,"expected_minutes":90,"deadline":"2026-11-20T18:00:00+03:00","subtasks":[{"title":"Решить","items":["Проверить ответ"]}]}}
```

Поля задачи/веса/два уровня берутся из T22. Идентификаторы создания выводятся из ключа источника, сохраняются между разными попытками разбора. Для новых веток при обновлении используется отдельное пространство UUID ключ+fingerprint: оно не пересекается с ветками первоначального создания.

Изменение задачи: `kind=task`, поле task соответствует T36 (`task_id`, changes/nodes/subtasks/weights), а before — конкретный исходный снимок. При первом связывании можно обновить уже существующую задачу; новое дерево не создаётся. Для уже связанного письма вид/UUID цели не меняются. Ответ без записи не является MailProposal и не должен попадать в apply.

Самостоятельное событие:

```json
{"kind":"event","event":{"title":"Пара по физике","start":"2026-11-20T10:00:00+03:00","end":"2026-11-20T11:30:00+03:00"}}
```

Обязательны название/aware start/end, конец позже начала. Точное время нормализуется прежним WorkBlock в UTC. task_id, команды, инструменты, удаление, смена вида связанной сущности, чужие поля/повторные JSON-ключи отклоняются. До 128 000 байт предложения; прочие ограничения прежних Task/WorkBlock и парсеров. Никаких автоматических календарных уведомлений/действий с Gmail.

`mail_preview(draft)` даёт текст полей/дерева либо «было → станет», ссылку источника и напоминание о подтверждении. QML выводит его как plain text. Предупреждение о пересечениях и снимок пересекающихся календарных записей добавляются в worker; перед записью снимок повторно проверяется внутри транзакции. После изменения календаря нужно обновить предпросмотр и подтвердить заново.

## Выполненные задачи

По ответу пользователя завершённый корень при обновлении из письма остаётся завершённым. Добавленные ветки и пункты также завершаются общим каскадным правилом. Явное предложение снять выполнение корня/потомка отклоняется. Прежние UUID и дата завершения корня сохраняются. Это отдельный параметр preserve_completed у parse_update; обычный поиск T36 по-прежнему исключает завершённые задачи.

## Запись и защита от повторов

`MailProposalService.source_state(source)` возвращает new/unchanged/changed/unavailable, прежнюю связь и доступную цель. Неизменённое письмо не нужно повторно отправлять модели; отсутствующая после удаления цель не создаётся повторно. Корзина и последующее восстановление возвращают ту же связь.

`MailProposalService.apply(draft)` повторно разбирает нормализованный payload, проверяет идентичность результата и вызывает TaskStore.apply_mail_proposal. В одной BEGIN IMMEDIATE:

1. Проверяется квитанция request ID + digest. Повтор возвращает прежний UUID даже после удаления записи, без её воскрешения. Иное содержание с тем же request ID отклоняется.
2. Сверяется полная прежняя связь (включая revision) и before задачи/события. Ручная правка, удаление или параллельная обработка требуют свежего предложения.
3. Записывается дерево либо самостоятельное событие, затем обновлённая связь источника и квитанция. Любая ошибка откатывает всё, включая task_identities/статистику завершения.

У другой генерации тот же ключ источника не сможет создать вторую запись: прежняя связь уже изменилась. Отдельные аккаунты с тем же Gmail ID имеют разные ключи. Связь/квитанции сохраняются и после корзины/окончательного удаления задачи или удаления события, чтобы повтор не воссоздавал его. Восстановление старого backup возвращает знание об обработке на момент того снимка, не будущие квитанции.

SQLite v12: source_links и индекс по цели, mail_proposals. Связь не имеет каскадного FK к цели — отсутствие записи является допустимой меткой прежней обработки. Квитанция ссылается на ключ источника. Тело письма и исходный ответ модели отдельными полями не сохраняются, только подтверждённые данные задачи/события, источник/отпечаток/ревизия и digest. Эти метаданные включаются в backup вместе с БД; токены и конфигурация Google — нет.

Профили v1–v11 мигрируют одной транзакцией, существующий Pomodoro v11 не создаётся заново. Проверка backup принимает v9/v10/v11/v12 и проверяет строки связей; более старые форматы архива не обещаются. Старую версию программы с профилем v12 не использовать. Все проверки — временные БД, личный профиль не открывался.

## Пользовательский поток T37c2

В помощнике выбрать модель, открыть «Источники — Gmail», явно подключить/прочитать источник и нажать нужное письмо в списке. Под текстом находятся запрос, сведения о получателе/данных и отдельное согласие на **этот** запрос. Повторная генерация и уточнение требуют нового согласия; каждый запрос содержит текущий полный запрос пользователя, выделенное письмо и свежий снимок данных. Обычная история чата/навык чата/файлы не подключаются.

Передаются тема, отправитель, дата и тело только выбранного письма; prompt, текущее время со смещением; публичная проекция активных задач T36. Для связанного письма дополнительно соответствующая задача (включая выполненную) либо событие. Категории/файлы/фокус/корзина/другие завершённые корни/токены/Google-конфигурация/невыбранные письма/произвольные заголовки/URL источника не передаются. До провайдера проверяются пределы письма и T36, общий JSON до 512 000 байт. Подключение с неизвестной операцией mail отклоняется.

Source state unchanged/unavailable останавливает генерацию до вызова модели. Ответ answer показывает уточнение без права записи. Предложение новой задачи, события либо правки существующей активной задачи разбирается по точному снимку; для уже связанного письма вид/UUID цели фиксированы. Выбранная модель может предложить правку имеющейся активной задачи вместо дубликата. Совпадения по смыслу требуют проверки пользователя: приложение не гарантирует распознавания всех разных писем об одном задании.

«Исправить предложение» открывает обычные поля: название, описание, сложность, минуты, дедлайн или начало/конец события, предложенные изменения пунктов, новые ветки/листья и веса. Даты имеют местное смещение, неотредактированное время сохраняет точность исходного предложения. «Проверить правки и обновить предпросмотр» повторно разбирает данные вне UI-потока; при ошибке запись недоступна до выхода из редактирования. JSON пользователь не редактирует. При существенном изменении замысла можно отменить предложение и сформулировать новый запрос.

«Подтвердить и сохранить предложение» отдельно от согласия на передачу вызывает проверяемый сервис с before/link и снимком пересечений. Кнопка не активна при редактировании/занятости. Только подтверждение пишет данные; ответ модели/preview ничего не сохраняет. Ссылки на источник доступны в задаче и редакторе календарной записи после перезапуска. Открытие ссылки — отдельное действие во внешнем Gmail; веб-интерфейс может сам отметить открытое письмо прочитанным, API-просмотр меток не меняет.

При смене письма, чтении/входе/выходе Gmail, изменении модели/аккаунта помощника, закрытии или отмене результат очищается; поздний ответ не даёт черновика/записи. Смена аккаунта помощника на время входа также блокирует отправку. Во время подтверждённой записи действия смены источника/модели заблокированы до её завершения. Ошибка устаревшего снимка сохраняет данные и требует нового запроса/предпросмотра. После перезапуска письма/черновики/ответы не восстанавливаются автоматически, квитанции/связи источников остаются в SQLite v12.

Request.operation=mail и Request.mail добавлены совместимо. MailAssistantController принадлежит GmailController, имеет отдельный worker, Event/ID и ключ подключения (адаптер/модель/аккаунт/вход). Отдельный mail_prompt разрешает только объявленные поля, не общую историю. ChatGPTAdapter использует существующий Responses transport и фиксированные MAIL_INSTRUCTIONS без дополнительных инструментов/загрузок/платного fallback. MockAdapter явно формирует только демонстрационную задачу по теме, не обещает понимания письма; для обновлений выдаёт пояснение без записи.

Проверить условия обработки конкретного подключения перед реальными письмами. [Документация OpenAI API](https://developers.openai.com/api/docs/guides/your-data) описывает правила API по умолчанию; не считать store:false обещанием нулевого хранения. Запросы по существующей подписке используют [поддерживаемый поток](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) и его [ограничения](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). Настоящая передача агентом не выполнялась; доступность и качество конкретного аккаунта требуют отдельной пробы.

T38 отменён пользователем 18 ноября: чтение сообщений Telegram/MCP исключено. Следующий этап T39 — по указанию пользователя и после согласования формулы роста/наград. Регистрация Telegram и Mini App остаются T41–T42.
