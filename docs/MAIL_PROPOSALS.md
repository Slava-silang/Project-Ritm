# Предложения из писем: ядро T37c1

Реализовано 16 ноября 2026 года. Это проверяемая Python-логика и хранение, **ещё не кнопки генерации в окне Gmail**. T37c остаётся в работе; T37c2 подключит выбор писем, модель, редактор и подтверждение. Реальная почта/модель не вызывались.

## Формат и границы

`SourceRef.from_mail(mail)` строится приложением из прочитанного письма, а не из ответа модели. Ключ — аккаунт+ID, fingerprint — содержание, URL — только Gmail с тем же аккаунтом/ID. Модель не может подменить source URL, fingerprint, аккаунт и права доступа. `SourceLink` хранит вид, UUID записи и ревизию связи.

`parse_mail_proposal(request_id, payload, source, link=None, before=None)` возвращает неизменяемый MailProposal. Пока один проверяемый объект — одна задача или самостоятельное событие из одного письма; группировку/перебор выбранных писем подключает T37c2. Не считать это готовой пакетной обработкой почты.

Создание задачи:

```json
{"kind":"task","task":{"title":"Подготовить лабораторную","difficulty":6,"expected_minutes":90,"deadline":"2026-11-20T18:00:00+03:00","subtasks":[{"title":"Решить","items":["Проверить ответ"]}]}}
```

Поля задачи/веса/два уровня берутся из T22. Идентификаторы создания выводятся из ключа источника, сохраняются между разными попытками разбора. Для новых веток при обновлении используется отдельное пространство UUID ключ+fingerprint: оно не пересекается с ветками первоначального создания.

Изменение задачи: `kind=task`, поле task соответствует T36 (`task_id`, changes/nodes/subtasks/weights), а before — конкретный исходный снимок. При первом связывании можно обновить уже существующую задачу; новое дерево не создаётся. Для уже связанного письма вид/UUID цели не меняются. Ответ без записи не является MailProposal и не должен попадать в apply.

Самостоятельное событие:

```json
{"kind":"event","event":{"title":"Пара по физике","start":"2026-11-20T10:00:00+03:00","end":"2026-11-20T11:30:00+03:00"}}
```

Обязательны название/aware start/end, конец позже начала. Точное время нормализуется прежним WorkBlock в UTC. task_id, команды, инструменты, удаление, смена вида связанной сущности, чужие поля/повторные JSON-ключи отклоняются. До 128 000 байт предложения; прочие ограничения прежних Task/WorkBlock и парсеров. Никаких автоматических календарных уведомлений/действий с Gmail.

`mail_preview(draft)` даёт текст полей/дерева либо «было → станет», ссылку источника и напоминание о подтверждении. В будущем QML выводить только plain text. Предупреждения пересечений/редактор/фактическая кнопка подтверждения относятся к T37c2; само существование Python apply не означает готового пользовательского потока.

## Выполненные задачи

По ответу пользователя завершённый корень при обновлении из письма остаётся завершённым. Добавленные ветки и пункты также завершаются общим каскадным правилом. Явное предложение снять выполнение корня/потомка отклоняется. Прежние UUID и дата завершения корня сохраняются. Это отдельный параметр preserve_completed у parse_update; обычный поиск T36 по-прежнему исключает завершённые задачи.

## Запись и защита от повторов

`MailProposalService.source_state(source)` возвращает new/unchanged/changed/unavailable, прежнюю связь и доступную цель. Неизменённое письмо не нужно повторно отправлять модели; отсутствующая после удаления цель не создаётся повторно. Корзина и последующее восстановление возвращают ту же связь.

`MailProposalService.apply(draft)` повторно разбирает нормализованный payload, проверяет идентичность результата и вызывает TaskStore.apply_mail_proposal. В одной BEGIN IMMEDIATE:

1. Проверяется квитанция request ID + digest. Повтор возвращает прежний UUID даже после удаления записи, без её воскрешения. Иное содержание с тем же request ID отклоняется.
2. Сверяется полная прежняя связь (включая revision) и before задачи/события. Ручная правка, удаление или параллельная обработка требуют свежего предложения.
3. Записывается дерево либо самостоятельное событие, затем обновлённая связь источника и квитанция. Любая ошибка откатывает всё, включая task_identities/статистику завершения.

У другой генерации тот же ключ источника не сможет создать вторую запись: прежняя связь уже изменилась. Отдельные аккаунты с тем же Gmail ID имеют разные ключи. Связь/квитанции сохраняются и после корзины/окончательного удаления задачи или удаления события, чтобы повтор не воссоздавал его. Восстановление старого backup возвращает знание об обработке на момент того снимка, не будущие квитанции.

SQLite v12: source_links и индекс по цели, mail_proposals. Связь не имеет каскадного FK к цели — отсутствие записи является допустимой меткой прежней обработки. Квитанция ссылается на ключ источника. Тело письма и исходный ответ модели отдельными полями не сохраняются, только подтверждённые данные задачи/события, источник/отпечаток/ревизия и digest. Эти метаданные включаются в backup вместе с БД; токены и конфигурация Google — нет.

Профили v1–v11 мигрируют одной транзакцией, существующий Pomodoro v11 не создаётся заново. Проверка backup принимает v9/v10/v11/v12 и проверяет строки связей; более старые форматы архива не обещаются. Старую версию программы с профилем v12 не использовать. Все проверки — временные БД, личный профиль не открывался.

## Следующий шаг T37c2

Подключить ядро к GmailController/выбранному адаптеру отдельно от обычной истории: только выбранные письма, список раскрытых данных и получатель/модель, отдельное подтверждение повторной передачи. Учитывать фактический snapshot связанных целей, включая выполненные/недоступные, без невыбранных вложений. Проверить условия обработки данных конкретного подключения перед реальной передачей. Просмотренная [документация данных OpenAI API](https://developers.openai.com/api/docs/guides/your-data) описывает API по умолчанию; не подменять ею без проверки условия конкретного аккаунта/режима Sign in with ChatGPT и не считать store:false обещанием нулевого хранения. [Возможности подключения](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Модель может вернуть предложение/уточнение, но не писать в БД напрямую. Редактор, точный предпросмотр, источник, предупреждения о календарных пересечениях, ручное подтверждение, отмена/смена модели/источника/аккаунта и перезапуск должны быть проверены в UI до завершения T37c. T38 отменён пользователем 18 ноября: чтение сообщений Telegram/MCP исключено. После T37 следующий этап — T39 по указанию пользователя; регистрация Telegram и Mini App остаются T41–T42.
