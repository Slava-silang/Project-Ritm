# T36 — поиск и подтверждаемые правки задач

## Пользовательский сценарий

В помощнике выбрать «Найти и изменить задачу». Например: «Есть ли у меня лабораторная по физике?» или «Перенеси дедлайн лабораторной по физике на 21 ноября в 18:45». Выбор задачи в основном окне не ограничивает поиск: модель получает все активные главные задачи с подзадачами. Если совпадение неоднозначно, помощник должен попросить уточнение.

Ответ без изменений остаётся сообщением в чате: кнопка применения недоступна, задача не создаётся и не меняется. Для предложения правок показываются выбранная задача и разница «было → станет». Можно исправить черновик, проверить его или уточнить запрос. Сохранение — отдельной кнопкой подтверждения. Если задача изменилась/удалена/завершена за время запроса, предложение нужно сформировать заново. Отмена/поздний ответ не сохраняют данные.

Новый режим имеет отдельный контекст диалога от создания, разбиения и планирования. Продолжение истории после перезапуска явное; прошлые снимки списка не отправляются как служебные данные, для каждого запроса читается свежий список. В истории остаются запросы/ответы и показанная разница; модель может процитировать данные задачи в ответе.

## Данные и допустимые действия

В запрос входят ID, названия, описания, дедлайны, состояние выполнения активных задач и ID/названия/отметки подзадач обоих уровней. Завершённые главные задачи, корзина, категории, календарь, фокус-сессии, метаданные файлов и учётные данные в снимок не добавляются. Текущее местное время со смещением передаётся для относительных дат. Вложения доступны по прежнему явному выбору T35; сам выбор модели задачи не предоставляет права читать её файлы.

Максимум 500 активных задач, 5000 вложенных пунктов и 256 000 байт JSON. Список не обрезается молча: превышение отклоняет запрос до обращения к провайдеру, можно использовать прежние режимы выбранной задачи. Создание/разбиение получают прежний контекст, планирование не расширяется этим этапом.

В одном предложении можно исправить одну активную задачу: название, описание, сложность, ожидаемые минуты, дедлайн или выполнение; переименовать/отметить существующие пункты, добавить новые подзадачи прежнего формата, задать веса. Применяются общие правила каскадного выполнения и весов. Отметки предка и потомка в одном предложении запрещены, чтобы порядок не менял смысл. Удаление/перемещение пунктов, изменение категории/календаря/файлов/фокуса не входят в T36.

## Контракт и проверка

`Request.tasks` — неизменяемый снимок, `current_time` — внедряемые часы. Перед запросом приложение проверяет размер, адаптер сериализует только публичную проекцию в user data. Статические инструкции отделены от текста задач, файлов и навыков. Ответ строго проверяется приложением; модель не получает исполняемых инструментов. Ориентиры: [роли и разделение инструкций/данных](https://developers.openai.com/api/docs/guides/prompt-engineering), [структурированные ответы и неразрешимые запросы](https://developers.openai.com/api/docs/guides/structured-outputs). HTTP-поля и поведение подписки остаются по [ограничениям SiwC](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations); новые API-параметры не добавляются.

Ответ без записи: `{"task_id": null, "answer": "Уточните название"}`; вместо null допустима строка UUID из снимка. Предложение: `{"task_id": "UUID", "changes": {...}, "nodes": [{"id":"UUID потомка", "title":"...", "completed":true}], "subtasks": [...], "weights": null}`. Поля кроме task_id необязательны, но нужно реальное изменение. Нельзя смешивать answer с изменениями. Чужие/повторяющиеся ID, неожиданные поля и невалидные значения отклоняются. Новые ID детерминированы прежним механизмом T22, существующие не заменяются.

TaskService повторно разбирает правки по исходной задаче и передаёт результат обычному TaskStore.apply_proposal: проверка полного baseline, дерево, выбранные ссылки материалов и квитанция записываются одной транзакцией. Повторное подтверждение идемпотентно, отказ не оставляет частичных изменений. Остальные задачи не переписываются. SQLite остаётся v11, новых зависимостей/файлов настроек нет.

Подменный помощник умеет только демонстрационный поиск точного названия; это явно тестовый режим. Проверки правок используют отдельный подменный адаптер. Возможности реальной модели/аккаунта проверяются отдельно, без автоматических платных запросов.
