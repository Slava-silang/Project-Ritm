# Достижения сада — T39c3a

Реализованы ядро достижений и атомарное применение к потоку событий. С T39c3c обычный интерфейс создаёт полный сервис в worker после явного включения. Принятые награды — GARDEN_ECONOMY.md; общие правила — SPEC S16. Backup обеих БД — PAIRED_BACKUP.md; настройка/ограничение выбора тем — GARDEN_RUNTIME.md.

## Правила

За первое знакомство — 100 монет, за первую действительно созданную после включения задачу — 300. Исходный снимок, восстановление из корзины и создание в выключенный период не дают награду задним числом. Регистрация Telegram не является событием этого этапа и не выдаёт 200 монет до T41.

Главная задача попадает в счётчик один раз по UUID, на новом завершении при включённом саде. Ветки сами не считаются главными задачами; завершение всего дерева даёт один корень. Повтор/отмена/восстановление, в том числе в новом месяце, не создают второй учёт того же UUID. Новое завершение задачи, ранее выполненной в выключенный период, может быть учтено впервые; само включение не пересчитывает её старый статус.

Оплаченные часы берутся только из новой основной оплаты T39c1: надбавки/достижения не добавляют часов, погашение долга/неоплаченный остаток/время сверх дневного предела/выключенные промежутки не входят. Для месячных целей используется местный месяц **исходного события, создавшего оплату**. Поздняя доставка очереди не меняет месяц; ручная запись прошлой даты оплачивается в месяце события её создания/правки. Остаток 2 минуты ноября + 3 декабря становится оплаченной пятиминуткой декабря.

За 5/15/30 главных задач и отдельно 5/15/30 оплаченных часов в одном месяце выдаются 50/150/300 монет, каждый порог один раз. Обе линии вместе дают максимум 1000 монет/месяц. В следующем месяце цели начинаются заново; знакомство/первая задача не повторяются. Достижения/валюта не отнимаются при исправлении или удалении времени; дальнейший долг продолжает учитываться T39c1.

«Космос» открывается после 30 оплаченных часов суммарно, «Джунгли» — после 15 уникальных главных задач суммарно. Открытия постоянные, без дополнительной валюты, светлая/тёмная темы доступны сразу. Ротация декоративных садов не удаляет постоянные UUID/открытия и финансовые пороги. С T39c3c Appearance проверяет открытия в worker, с сохранением ранее выбранной темы (GARDEN_RUNTIME.md); оформление тем остаётся заготовкой.

## Модель и хранение

Domain/garden_achievements.py: immutable AchievementState/MonthProgress и чистый advance_achievements. Состояние содержит знакомство/первую задачу, отсортированные уникальные UUID, постоянное оплаченное время, месяцы/полученные пороги и открытые темы. Валидируются типы, уникальность, суммы по месяцам и соответствие порогов/тем счётчикам. Codec отвергает неизвестные/повторные поля и повреждённые данные без сброса. AchievementReward также содержит новые ID для будущего отображения; GUI этим шагом не добавлен.

GardenStore v5 добавляет отдельный singleton garden_achievement_state, achievement_snapshot возвращает проверяемое состояние. Миграция с v1–v4 сохраняет кошелёк/имущество/журнал времени/курсор/прежние надбавки и создаёт пустое состояние достижений. Старые события не переигрываются ради новых наград. Если старый прототип уже включён, знакомство выдаётся только на первом новом допустимом событии с новым режимом, без ретроактивных часов/завершений.

GardenEventService(..., award_achievements=True) включает полный расчёт. Значение False по умолчанию оставлено для прежнего внутреннего протокола/его проверок; это не пользовательская настройка и не способ выключать сад. После первой награды попытка обработать новое событие режимом без достижений отклоняется. Пользовательское выключение — отдельное событие enabled=False; полный сервис продолжает понимать его окна и сохраняет полученное.

Apply_event получает состояние достижений внутри BEGIN IMMEDIATE. Новые достижения, payments/claims, журнал времени, курсор/зеркало и кошелёк/revision/квитанция сохраняются вместе. Отказ записи откатывает всё, повтор не выдаёт валюту второй раз. Восстановление старого распределения v3 не включает достижения и не выдаёт исторические монеты.

До обычного профиля нужны T39c3b/T39c3c: согласованные снимки и аварийное восстановление двух БД, worker/явная настройка включения, live-checkpoint перед завершением задачи/выключением, учёт аварийного восстановления и применение списка открытых тем. Сад автоматически не включать.


T39c3b завершён: обе базы входят в согласованную копию и безопасно восстанавливаются вместе с достижениями. Текущая версия сада v6; следующая интеграция worker/настройки/тем — T39c3c. Детали нового поколения и совместимости старых архивов — PAIRED_BACKUP.md.

T39c3c подключает worker/явную настройку/темы в обычном приложении. Выключенный сад сохраняет достижения и открытые темы; периодический live-таймер остановлен. Read model перечитывается после restore даже при меньшем revision. Поле/магазин — T39d.

## T39d3 — представление достижений

«Прогресс» на странице сада открывает отдельный GardenProgress.qml. В компактном
окне и при недоступной графике кнопка также доступна в верхней строке; выключение
сада не скрывает полученные достижения. Выбор месяца показывает шесть целей
(5/15/30 главных задач и 5/15/30 оплаченных часов), фактический счётчик, полосу,
заранее известную награду и текст «получено»/«ещё не получена». Итог за месяц
суммирует только его сохранённые награды целей, а не кошелёк/надбавки.

Отдельно показаны постоянные знакомство/первая новая задача и условия/статус
космоса/джунглей. Telegram до реализации регистрации не показывается как
действующее достижение. Светлая/тёмная темы доступны сразу.

Application/garden_progress.py готовит чистый read model из AchievementState.
Пороги/суммы месячных целей берутся из доменного THRESHOLDS, статус — из
сохранённых claimed/themes, а не округлённого текста часов. Внутренние точные
числа остаются прежними; в карточках дробные часы обрезаются до сотых, полосы
ограничены 100%. Для текущего местного месяца без событий добавляется пустая
строка только в снимке интерфейса, без записи в базу. Остальные месяцы —
сохранённый журнал достижений, а не архив предметов будущего T39e.

Просмотр/переключение месяцев не начисляют валюту, не меняют revision и не
пересчитывают историю. Снимок обновляется в worker при обычном sync, включая
restore с меньшими счётчиками. Если доставка недоступна, диалог показывает
ошибку и скрывает показатели вместо выдачи ошибочного нуля за сохранённый
результат. После повторного обновления данные возвращаются. Escape закрывает
диалог; сочетания перехода разделов блокируются, пока он открыт.
