# Проекция и ограниченное облачное хранение — T41b3

`integrations/sync_projection.py` — чистые функции без SQL/сети/профиля.
Принимают неизменяемые DTO, возвращают предложения; ничего не удаляют и не
отправляют. Реальный adapter к TaskStore/очередь/подтверждение — T41c.

## Уточнение пользователя 26 ноября

Лимит 50 применяется суммарно к обычным завершённым задачам и прошлым выполненным
повторам (occurrence). Текущие экземпляры действующих регулярных расписаний
остаются отдельно, даже уже выполненные: это шаблоны следующего повтора.
Будущий первый экземпляр тоже остаётся внутри regular. Это не обещание общего
предела размера облака: активные задачи/шаблоны/категории/служебные marks тоже
занимают место. Локальная история не ограничивается.

## Начальный локальный отбор

LocalData содержит tuples TaskRecord/RegularRecord/OccurrenceRecord/CategoryRecord/
BlockRecord, необязательный общий CalendarRecord, sets skipped/deleted UUID.
Записей trash.before/after, вложений/файлов/фокуса/сада/ключей в этом типе нет.
Источник должен брать живые записи и явные состояния, не восстанавливать Task
из корзины без её признака: по одному Task невозможно распознать происхождение.

project_local:

- проверяет поля/граф; canonical DTO не изменяют исходные записи;
- убирает отмеченные skipped/deleted корни и их блоки, не создавая из них history;
- обычный Task, уже представленный current/history, не дублирует; несовпадение
  тела источника с агрегатом — ошибка, а не молчаливое предпочтение одной версии;
- сохраняет все активные ordinary и все действующие regular;
- предлагает 50 последних завершённых ordinary+occurrence по имеющимся
  completed_at; при одинаковом времени порядок стабилен по UUID;
- если завершённых больше 50 и есть неизвестные даты, не выдаёт результат:
  CompletionSelectionRequired содержит только unknown_ids/suggested_ids для
  будущего предпросмотра. Пользователь может передать явный набор до 50 корней;
- если всего не больше 50, сохраняет и недатированные, сообщает unknown IDs,
  никогда не заполняет completed_at придуманным временем. Первый импорт всё
  равно требует ранее согласованного общего backup/предпросмотра/подтверждения.

selected_completed — именно UUID корней, не UUID history-обёрток. Набор не
должен включать неизвестные/активные корни или превышать лимит. unknown IDs
остаются признаком неопределённости и после выбора, чтобы UI мог её показать.
LocalExclusion — местный отчёт UUID/причины, не серверный tombstone и не команда
удалить что-либо. У него нет доверенной облачной revision/delete_epoch.

Календарь выбирается по концу интервала: ends_at >= now UTC − 30 суток.
Граница включительна с микросекундами. Будущие/текущие события сохраняются,
пересечения не разрешаются удалением. Часовой пояс регулярности не меняет эту
UTC-длительность. Старые блоки не отправляются, локальная запись остаётся.

Если завершённая задача не вошла в лимит, её подходящий по времени блок хранит
минимальную подпись (title) и UUID, без описания/подзадач. Уже имевшаяся архивная
подпись допустима и без локального дерева. При отсутствии источника/подписи блок
не отправляется: данные не берутся из корзины и не выдумываются. Явно удалённый
корень убирает и подпись. При наличии полного живого корня лишняя подпись очищается.

Выход ограничен 10000 объектов/32 МиБ канонических entity-байтов: отказ без
усечения при превышении. Это не квота сервера. Последующая упаковка страниц
имеет собственный лимит, включая оболочки, и тоже может безопасно отказать.

## Чистый план серверной очистки

retain_cloud(snapshot, completion_order, now, revision) принимает уже изолированный
снимок аккаунта и отдельный порядок переходов в completed, UUID корня →
положительный серверный номер. У каждого completed ordinary/occurrence он обязателен,
даже при менее 50 записях. Обычная правка/переименование, revision объекта и
часы устройства не используются для продвижения в этом порядке. При равном
номере (например, общий импорт) стабильно сравниваются UUID. Начальный порядок
импорта должен отражать принятый предпросмотр; даты при этом не выдумываются.

Функция возвращает RetentionPlan(entries, effects, revision):

- сверхлимитные завершённые тела заменяются removed/task или removed/occurrence
  с reason=retention, той же delete_epoch и новой revision;
- occurrence mark содержит UUID history и исходного корня, без текста;
- истёкшие календарные тела заменяются removed/block с retention;
- блок явно удалённого корня заменяется user_deleted mark с ростом собственного
  барьера на 1, даже если раньше у него была архивная подпись;
- подходящий по времени блок вытесненного корня получает только title/связь;
- лишняя подпись уже доступного живого корня очищается;
- правила/current templates, активные задачи, категории/общий пояс и прежние
  служебные marks сохраняются. Последние нужны против старых устройств.

Все effects принадлежат одной предложенной revision, большей revision снимка.
Нужна будущая транзакция применения; только она сделает очистку действительной.
При отсутствии изменений effects пусты и revision снимка не продвигается.
Повторный план над уже очищенным результатом не создаёт новых effects.

Нет таблицы серверных completion-order, owner/auth, реального удаления SQLite/
WAL, квот/замера объёма, ретраев, сохранения outbox или применения в desktop.
Нельзя по этим функциям объявлять безопасную работающую синхронизацию. Вход
должен быть авторизован/проверен вызывающим сервером; source adapter ещё не готов.
Схемы tasks v14/garden v7, зависимости и реальный пользовательский профиль прежние.
