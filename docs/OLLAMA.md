# Локальные модели — T40d

## T40d1: готовый адаптер, ещё без панели

`integrations/ollama.py` подключается к уже работающему серверу Ollama на
127.0.0.1:11434. Не устанавливает Ollama, не скачивает/не удаляет модели,
не читает ключи, не вызывает облачный API. Зависимости/схемы БД не меняются.
Панель выбора в помощнике остаётся T40d2, поэтому в интерфейсе это подключение
пока не доступно. Модели/сервер на компьютере пользователя не проверялись.

GET /api/tags загружает установленные имена, фильтруя remote_host/remote_model,
:cloud, дубликаты и неподходящие имена. Перед передачей текста задачи POST
/api/show проверяет выбранную модель: отсутствие remote-признаков, локальный
формат gguf/safetensors и capability completion. Облачный псевдоним блокируется
до отправки контекста. Это проверка метаданных доверенного локального сервера,
не гарантия поведения произвольного прокси. Для строгого локального режима
сам Ollama рекомендует OLLAMA_NO_CLOUD=1 с перезапуском сервера; приложение
не меняет пользовательские/системные настройки.

POST /api/chat отправляет общий prepare_text пяти операций как system/user,
stream:false, format:json, без инструментов/ключей. Ответ должен быть
завершённым сообщением assistant выбранной модели, без tool_calls/remote,
не более 128 КБ. Парсеры/редактирование/подтверждение остаются прежними;
сам адаптер задачи не записывает. Бинарные файлы/изображения не поддержаны;
для текстовых материалов используется существующий prepare_sources.

HTTP-транспорт допускает только эти три метода/пути и числовой локальный
адрес; не следует перенаправлениям, не использует proxy из окружения.
Чтение ограничено 2 МиБ. Сокет работает в отдельном потоке; основной worker
наблюдает отмену/общий deadline, shutdown прерывает ожидание заголовков и
тела. Подключение к порту ограничено двумя секундами, запрос — 120 секундами,
список моделей — 10. Отмена закрывает соединение, но момент освобождения GPU
или прекращения вычисления на стороне Ollama не гарантируется приложением.
Ошибки возвращаются фиксированными сообщениями без сырого HTTP-ответа.

## Проверки

Fake-транспорт покрывает контекст пяти операций, локальные/облачные/embedding
модели, повреждённые метаданные и ответы, отсутствие инструментов, отмену до
запроса/после проверки модели и разбор в черновик. Подменный loopback-сервер
проверяет запрос без ключа/proxy, отказ redirect/большого и повреждённого
ответа, прерывание ожидания заголовков/тела с освобождением потока.
Фактические результаты — TESTING/STATUS. Настоящая Ollama/генерация, UI и
Windows не проверены, внешние модели не загружались.
